Add approval requests, the requests-queue limits and `clientRequestId` idempotency to the core. `client.approvalService.request` stores a pending request bound to the action digest (strict per-tool action schema, checked summary, 24-hour TTL or the commitment scope's earlier expiry) and hands it to the approval channel; `authorize` and `use` let an approved ID run the identical action once, with the owner's decision re-verified, policy evaluated again and a compare-and-set to `void` in the effect transaction; `collect` applies a signed decision from the channel only through `ownerActions.apply`; `expireDue` marks lapsed requests. `feeContextFromQuote` builds an approval fee from one quote. Inbound requests from unknown senders are limited to 5 per sender key and 200 in total (refused envelopes from unknown keys count), counted in the transaction that stores them; `client.requests` lists, counts and ignores them, and `queueRefusals` gives the owner's aggregated count. `client.idempotency` implements 07 §3.3 (keyed request digest, execution lease, compare-and-set on every effect and on finish, `IDEMPOTENCY_KEY_REUSED`, stale `pending_approval` not replayed). `checkApproval` now reports `void` for a used approval. `StoreCipher` gains an optional `indexDigest`; without it idempotency fails closed.
