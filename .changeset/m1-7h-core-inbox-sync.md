Add inbox sync, delivery acknowledgements and the fetch-only catch-up to the core (M1-7h). `client.syncInbox({budgetMs})` reads the agent's own relays for its keys at every epoch through transport-nostr's sync (per-relay cursor with the 48 h look-back, dedup by gift-wrap ID), skips an envelope whose hash is already in the seen-set, so each envelope's signature is verified once, stores new envelopes, drops a contact's envelopes above `contacts.rateLimitPerContactPerHour` (counted once, per contact, in a sliding hour) and then processes what is stored, `card-update` first. It returns the new messages from contacts with the metadata of the untrusted-content wrapper (the sender under the contact-name rule with its identity label, the short owner fingerprint, the self-declared name for the block's `from` only), the processing outcomes, the requests count and the rate-limited counts. `client.catchUp({budgetMs})` only fetches and stores and returns `{inbox: [{contactId, unread}], requests}` from the store; it processes nothing (no handshake, ack, card update, receipt or read mark). With `AgentLinkClient.create({deliveryAcks: true})` (off by default, 02 F-23), `syncInbox` sends one signed `ack` (`{kind: "received", envelopeId}`, `replyTo` the message) per new message from a contact, never for an ack, and `client.acks.status(envelopeId)` reports whether that contact acknowledged a sent message. The Transport interface gains an optional `sync`, which `nostrTransport` implements. A `revoke` envelope is verified against the named agent's stored card and applied (`revoked_agents`, contact status `revoked` or the own identity revoked, pending outbox rows to that agent stopped as `revoked`) or dropped; it never stays `received`. The per-contact rate limit is counted where the contact's envelope is stored (`EnvelopeService` gains optional hooks, `revocation` and `rateLimit`, and the reasons `revoke_invalid` and `rate_limited`).
