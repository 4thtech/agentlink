Add the owner's answers to requests from unknown senders and refused-row retention to the core (M1-7e-2, D-72). `client.requests` gains `accept(requestId)` (flags that one request row readable; it still counts toward the limits, and no contact or pairing is written), `ignore(fromKey)` (now also removes the key's refusals), `ignoreAll()`, `block(requestId)` (adds the key to `blocked_keys` and removes its requests, refusals and held envelopes in one transaction), `unblock(fromKey)` (by key, never by the sender-chosen envelope ID) and `listBlocked()`; `list()` entries carry `acceptedAt`. Envelopes from a blocked key are dropped at the start of 04 §3.1.1 step 5, before any decryption, with the new fixed reason `sender_blocked`; a contact's card-update from a blocked new epoch key still applies and removes the block, and a pairing message from a blocked key is always dropped. Refusals from unknown keys stop counting 7 days after the local `refused_at` (or when `refused_at` is more than 300 s ahead) and are pruned at the start of each processing pass. `requestsFullTx` now takes `now`. The idempotency `begin` refuses a `clientRequestId` outside 1 to 256 UTF-8 bytes and a tool name outside the 06 §2.0 set with `idempotency_args_invalid`. Store schema version 2: `envelopes.refused_at`, `envelopes.request_accepted_at` and the `blocked_keys` table; the Node SQLite store migrates a version 1 file forward.
