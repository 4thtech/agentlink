Add the send pipeline, the Transport adapter and the outbox over the Store to the core (M1-7k). `client.sendMessage({to, text | body, type, replyTo, clientRequestId})` sends a Talk message (`text`, `note`, `request`, `delivery`) to a paired contact: a `body` with a `terms` key returns `USE_TERMS_TOOLS` and stores nothing; the agent must be able to send and the policy must allow the contact (a paired contact may Talk while the policy fails closed, D-70), otherwise nothing is stored or published; one gift wrap per distinct recipient key, each routed to the relay list of the agent it concerns (the contact's list for the contact's agent and owner, the own list for the own owner and agent, the union when one owner owns both); the envelope and all of its outbox rows are stored in one transaction before the first publish; repeats under one `clientRequestId` return the original result and a different request returns `IDEMPOTENCY_KEY_REUSED`. `nostrTransport({connector, addressCheck, nip11})` builds the Transport from the runtime's relay I/O and is passed to `AgentLinkClient.create({transport})`; NIP-42 AUTH is signed only on the agent's own relays. `client.outbox.processDue()` gives staged envelopes (a pairing handshake or handshake-ack) their wraps once, then publishes due rows through transport-nostr's OutboxWorker; a per-row claim lets only one of several processes sharing the store republish a row, and another takes it over within 30 s if that process stalls or dies. `EnvelopeService.prepare` builds an envelope without storing it.
