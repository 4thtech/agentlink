Add the key interfaces of G-2 (04 §3.1.1) as types in the main entry, so transport and core can name them: `EnvelopeKeys` (`signEnvelopeHash`, `signNostr`, `nip44Encrypt`, `nip44Decrypt`, `unwrapCek`), implemented by `KeyStore` (which adds `getPublicBundle` and `sign712`) and by `OwnerSession` (which adds `signOwnerAction` and `sign712`). No method returns a private key or a seed, no method signs an untagged digest, there is no `hpkeOpen`, and only the decrypting methods and `getPublicBundle` take a key epoch. Owner signatures exist only on a short-lived session from `OwnerKeyStore.unlock(presence)`; it expires on a monotonic clock, is wiped on lock, signs only seal and AUTH Nostr events, and has epoch 0 only, and `lock()` cancels an unlock in flight. Add NIP-44 v2 through `@noble` with strict size, version, base64, MAC and padding checks, Nostr event ids and verification, and a NIP-59 gift wrap whose ephemeral key never leaves the package. `unwrapCek` opens one recipient entry through M1-1c's CEK unwrap with the key of the requested epoch (an owner session: the owner enc key). `MemoryKeyStore` and `MemoryOwnerKeyStore` (not for production) live in the package's one test seam, which is never built or exported, and the NIP-44 functions that take a secret or conversation key are exported only from `@agentlink/crypto/keystore`.
