M1-PAY-CONFIRM-b: the confirmation sheet for paid actions (b11 §19, §20; 04 §2.5.3; D-132). The approval page opens it for a request that costs credits (its card has its own Approve; it is never a list item), and the app's Rules page for a change to a spending limit: one modal sheet with the amount and what it is for, built only from the statement the server returned, the platform's check ("Confirm with Touch ID", "Windows Hello", "your passkey"), the backup code as a small link, every state with a reduced-motion version, and an automatic close about 1.2 s after Done. `POST /api/ui/pay-confirm/begin` takes `remember: true` for "Remember for this contact" (both bodies in one challenge; `rememberOffered` says when core offers it; `not_offered` otherwise). Approval views carry `paid`. A passkey whose PRF works only on use now sends the `create()` authenticator data with its registration, so its credential key is kept for paid actions (#581 audit).
