- **Specs:** none

## Decision

**Product name and brand system.** The product is named **AgentLink**, endorsed "by 4thTech" with its own visual identity (D-42). The design brief (11) now specifies the full brand system (mark, wordmark and lockups; app icons for macOS, Windows and Linux; PWA, iOS home-screen and Web Push icons; favicon; tray and menu-bar icons; colour for light, dark and increased contrast; type; iconography; illustration and motion; voice) and every surface per platform, including the desktop apps, the cloud agent pages, terminal copy and printed proof records. `project/design/claude-design-handoff.md` is the paste-ready package for Claude Design, derived from 11 (11 wins on conflict). The brand core moves into D1 and the OS and PWA icons into D2, because the M1 local UI, the Claude Desktop extension, the M2 desktop apps and the console PWA need them; D3 keeps the marketing site and the final brand. **Working domain: `myagentlink.xyz`.** Risk, not blocking: owner passkeys bind to the WebAuthn RP ID of the production console domain (D-38), so the domain is final only after the trademark check (M1-24) and the domain decision (M2-10). Until the check clears, strings keep `{productName}` and the wordmark stays separable, so a rename is an asset swap rather than a redesign. For the M2-10 security review: an RP ID set to the console host, rather than the registrable domain, keeps other subdomains (`pay.`, `invite.`, `verify.`) from requesting the owner passkey; passkeys created on the beta hosts do not carry over to production. **Resolves D-14.**
