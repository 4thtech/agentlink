## Decision

**Automated delivery pipeline (decided by Tali in chat, 14 Oct 2026).** Every task follows one pipeline: develop (worker, own branch, worktree and PR) → independent audit (fresh-context reviewer, spec and diff only, report `IR-<task>-<n>`, required for S1/S2) → all required CI checks green → auto-merge into `main`. If CI cannot catch a class of problem, CI is improved (a follow-up card), never skipped. S0/S1: the orchestrator enables auto-merge after the audit passes. S2 and sensitive paths: same pipeline, but auto-merge is enabled only after Tali's one-word "merge" in chat, recorded in the PR body; no non-author GitHub approval is required (agents run under Tali's account, D-51), and `review-gate` (d) checks only the Threat note and Tests-first evidence. **Deployment:** a merge to `main` deploys to staging; services (Workers, sites, the submitter) deploy to production automatically once the staging deploy and smoke tests are green, which supersedes the "production waits for the owner's approval click" part of D-25 for them; `DEPLOY_FREEZE` still halts everything. The owner removes the required reviewer from the `production` Environment himself when the first deployable app exists (M1b). **npm `latest` is the exception (owner decision, 14 Oct 2026):** publish and rollback stay behind the owner's approval click (the `npm-publish` Environment keeps its required reviewer, with no removal date), while merged code still goes out automatically under `next`. Desktop app releases (signed binaries) and cloud-agent template releases keep the owner's click for the same reason: like npm they land on users' machines or infrastructure. Reason: an npm release lands on users' machines and is the classic supply-chain vector, while a service deploy rolls back in seconds. **Go-ahead model:** one owner go-ahead can cover a whole piece of work ("M1a crypto: merge when green"); without one, the orchestrator stops and asks before merging S2 or sensitive paths; a go-ahead never carries over to unrelated work. **Verify by content:** agents hold no production credentials, so CI deploys and records the artifact hash and deployed version ID; a deploy counts as done only when the orchestrator has compared the live version ID and served asset hashes with that record and with the build of `main` (npm: `dist.integrity` and provenance against the CI build) and made one live observation that only the new code produces (`project/process/delivery-process.md`). Unchanged and owner-only: mainnet contract deployments and upgrades, Safe operations, production secrets, clearing `DEPLOY_FREEZE`. Private repos (no rulesets on the Free plan): merge on Tali's per-PR instruction. Revisit before M3 (mainnet), together with D-51. Amends D-25
