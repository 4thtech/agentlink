# D-128: Owner-signed JSON is verified from the exact text received, strictly

- **Status:** Decided (owner, 23 Oct 2026)
- **Date:** 2026-10-23
- **Specs:** 04
- **Index:** [all decisions](README.md)

## Decision

**Owner-signed JSON is verified from the exact text received, strictly.** **Decided by Tali in chat, 2026-10-23** (option 1, strict). *Orchestrator wording, not the owner's words:* when verifying an owner-signed object from the text received, the parser refuses any duplicate member name and any member name written with an escape sequence (I-JSON, RFC 7493), at any depth, before the encoding, schema and signature checks; then the JCS signature is verified. It applies to every `SignedOwnerAction` op, the envelope that carries one and the card JSON form (04 §2.5.1). A refusal is `malformed`, fails closed and is never normalised. It closes parser-differential attacks on owner-signed objects (I-4, I-8). Byte-exact JCS text is not required, so a transport that re-serialises still works. Spec: 04 §2.5.1; vectors and implementation: M1-1h-b.
