## Decision

**MCP server: the official `@modelcontextprotocol/sdk`, with a module-graph guard on the stdio path.** **Decided by Tali in chat, 2026-10-15: "we go with A, we use MCP SDK fully where needed".** The MCP server uses the official `@modelcontextprotocol/sdk` in full where needed (M1-9c owns the pin and its allowlist row). A module-graph guard test in `apps/cli` makes sure the SDK's crypto-capable transitive packages (`jose`, `pkce-challenge`, `cookie-signature` and `etag`, and `hono`'s crypto) are never loaded on the stdio path: it loads the stdio entry point and fails if any of them enters the module graph. This keeps I-8 meaningful (all crypto goes through `@agentlink/crypto`; the allowlisted primitive dependencies are unchanged) while the SDK stays unmodified. Revisit if a future SDK version forces them onto the stdio path.
