## Decision

**0.3.0 first run: passkey-first approvals, the owner code as a saved backup, and agent-guided setup.** **Decided by Tali in chat, 2026-10-25:** "all as recommended" (decisions 1 to 7 of the UX-v2 onboarding plan, after the owner's two-computer test of 2026-10-25). *Orchestrator wording, not the owner's words:* (1) the passkey on a platform authenticator (Touch ID, Windows Hello) with PRF is the main way to approve; the owner code is generated at first run and shown once on the first-run page as the backup, with a save step that lets the browser's password manager store it and an "I saved it" step; it never appears in a tool result or in output an AI reads; (2) one owner confirmation at first run creates the owner key, registers the passkey, signs the agent's first card and signs its first policy (the 06 §3 defaults with `~/AgentLink/Send` allowed), as one owner flow of 04 §2.5; (3) the AI may cause the local pages to open in the owner's browser (an agent-run `agentlink ui` or `init`, and the MCP server's automatic open on `pending_approval` and on the missing-folder `needs_setup`), always through the OS opener; it never receives the one-shot session link, a session token, the owner code or a safety code, and it can never approve; (4) `init`'s "Set up AgentLink in all N apps?" defaults to No (Enter changes nothing); (5) "my other computer" in 0.3.0 is a second owner, paired like any contact, with an owner-set local label; one owner on several computers is M2; (6) "Remember for this contact" beyond proofs moves to M2 (spec note only, 06 §3); (7) `init` never writes Claude Desktop's config while Claude Desktop runs; the signed one-click extension (D-91, M1-9f) becomes the recommended Claude Desktop path once its manual check passes. **Threat note (author):** I-4 and the G-1 residual (D-67) are unchanged. The AI gains no way to produce a `SignedOwnerAction`: opening a page needs no secret, every owner operation on it still needs the gesture or the code, and a shell-capable agent can already start a page or fake a terminal (04 §2.5). **Open question Q-130-1 (owner):** an owner code saved in the browser's password manager for `localhost`, or shown on screen once, can be read or filled in by a program that drives the owner's screen or browser as the same OS user (computer use, browser-control extensions); the 04 §2.5 conditions name memory and clipboard reads but not screen or browser control. Proposed: name it as a G-1 residual, keep the passkey as the default because such a program cannot make the biometric gesture, and have the backup-code field ask the browser not to fill it in (browsers may ignore this); a password manager keys a saved code by host, so it may also offer a code saved for `localhost` to a look-alike page on another local port, which is part of the fake-prompt residual.
