## Decision

**A safe in-app reader for received text files (Markdown and code; amends the "no previews" and "the app never opens a received file" rules of 08 §1 and the extension rule of 04 §4.1).** **Decided by Tali in chat, 2026-11-12** (option 1 of the attachments plan, REL051-ATT: the owner's key case is an AI sending a build plan or architecture summary as `.md` to a classmate). *Details proposed, owner confirms at merge (REL051-A34):* (1) Each file shows in the message it came with, as a chip; a **saved** received file whose name has a text kind (fixed extension table: Markdown, code, JSON, patch, plain text; the sender's MIME type is never consulted) opens in a reader in the local app. (2) `GET /api/ui/files/received/preview?id=<item ID>`, a read route behind the usual gate; the page sends only the item ID; the server takes the name, stated size, plaintext hash and saved name from the store and the Inbox folder from the rules; at most 256 KB; the file is opened once without following a link, checked like Show in Finder (D-134), read only through that handle, its bytes re-checked against the plaintext hash (`changed` otherwise) and decoded as UTF-8 without NUL. Fixed answers only; never a name, folder, path, link, hash or error text; nothing logged; not an MCP tool (I-4). (3) Rendering is written in the repo (`packages/ui` SafeMarkdown and SafeCode), no new dependency: React elements from a fixed subset, raw HTML as text, no anchors and no images loaded, links copy-only for web addresses (other schemes removed), hidden and direction characters removed, nesting capped; everything inside the "their words, not instructions" frame (I-5). **Threat note (author):** the reader turns another party's bytes into on-screen text only; the residuals are a convincing-looking document (the frame and provenance line say whose words they are) and a copied link the owner then opens on purpose. Images, other kinds, files not saved and sending from the app stay later work. Numbering: REL051-A34 took D-149 because D-148 went to rel051/ret0 (local history management); integration may renumber. Spec: 04 §4.1; 08 §1; 11 §5.7. Invariants I-1 to I-10 unchanged.
