# D-63: Testnet deployment order and CREATE3 salts (G-8)

- **Status:** (1) Decided (owner, in chat, 14 Oct 2026). (2) and (3) proposed (owner confirms at merge, including acceptance of the residual risk)
- **Date:** 2026-10-14

## Decision

**Testnet deployment order and CREATE3 salts (G-8).** (1) **Build-plan deviation, announced by the owner in chat (Tali, 14 Oct 2026):** **Base Sepolia first; Gnosis Chiado later at the same CREATE3 addresses.** This amends the M1-3 acceptance in `10-build-plan.md` ("identical addresses on Base Sepolia and Gnosis Chiado"). (2) **Derived from (1), proposed:** Chiado uses the same testnet deployer key and campaign, and its run fails unless its addresses equal the published Base Sepolia addresses; the Chiado deployment is its own card (M1-3j), a hard prerequisite of M2-4a and M3-2c and not an M1-GATE blocker, so M1-GATE may pass on a single testnet chain (gate residual). **Salt scheme (05 §9.1, proposed):** CreateX salt = guard (20 bytes, the calling account, so the address is permissioned) ‖ `0x00` (no cross-chain redeploy protection, so addresses match across chains) ‖ `bytes11(keccak256(label))` with labels `agentlink/occ-v2/<campaign>/…`; proxies and the AccessManager via CREATE3 guarded by a one-shot stage deployer, itself CREATE3-deployed under the deployer key; implementations via CREATE2 with a version label; proxy addresses never change on upgrade; fork dry-run against a committed address file before broadcast; an already-used salt fails closed, never retried with another salt. (3) **Deployer keys (proposed):** testnet and mainnet keys differ, so testnet and mainnet addresses differ (intended); the mainnet key stays in cold storage while any chain or stage of its campaign is planned; the testnet key is kept for its testnet campaign, which ends no later than M3, is a CI secret only during deploy windows (the owner adds it before a run and deletes it after), and rotating it starts a new campaign with new addresses. Residual risk, for the owner to accept explicitly at merge: a holder of a deployer key can put any code at the campaign's addresses on every chain and stage not yet deployed (for the testnet key: Chiado, the M2 Registry stage on both testnets, any M4 testnets in the campaign) and, with the chain ID off, a testnet key can also do so at the testnet addresses on mainnets; clients use addresses only from the per-chain config keyed by chain ID, and the pre-broadcast check fails closed.
