# D-142: Incoming files are saved automatically into a folder the owner chooses once

- **Date:** 2026-10-29
- **Specs:** 04, 06, 08, 11

## Decision

**Incoming files are saved automatically into a folder the owner chooses once (wave 4; replaces "files are fetched only when the owner or the AI asks").** **Decided by Tali in chat, 2026-10-29** (Decision 47, Q3: files that arrive are saved automatically into a folder chosen once, with "Show in Finder"; a spec change with a Fable review first). *Details proposed, owner confirms at merge (W4-AUTO-SAVE):* (1) **What happens.** When a file arrives from a contact, the agent's core downloads it, decrypts it locally, checks both hashes and saves it into the Inbox folder (`files.inboxFolder`, default `~/AgentLink/Inbox`, changeable in Settings), with the same fetch as `agentlink_fetch_file` (04 §4); the app shows "Saved to {folder}" with Show in Finder (D-134). Nothing new is sent to any 4thTech service and nothing new is logged (zero access, I-7). (2) **Only from contacts the owner keeps.** Only files from a paired contact that `contacts.allowed` allows and that is not blocked, removed or revoked, re-checked right before the download; never from an unknown sender's request, never for a cloud agent (no disk, 06 §2.3). (3) **Limits** (cost bounds, not a security boundary; 04 §4.1): per contact per rolling 24 h at most 50 files and 500 MB; for all contacts of one agent at most 200 files and 2 048 MB; per file `files.maxReceiveSizeMB` as today; at least 1 GiB stays free on the folder's disk. A file over a limit arrives and waits for Save, as today. (4) **The owner stays in control:** a global switch in Settings (`files.autoSave.on`), a per-contact "Ask before saving" (`contactRules[].files.askBeforeSaving`), both owner-signed `policy.set` with presence; files that are not saved automatically keep today's save-on-request paths (Save in the app, W4-FILES-SAVE `file.save`; or the AI's `agentlink_fetch_file`). (5) **Disk safety** (04 §4.1): a quarantine mark on every saved file (macOS `com.apple.quarantine`, Windows Mark-of-the-Web `Zone.Identifier` with `ZoneId=3`), never with the file's link; never opened, run, previewed or unpacked by AgentLink and never made executable; the extension decides nothing; names sanitised (bidi and zero-width characters, reserved names, length); realpath and no symlink following; never overwrites. (6) **`agentlink_fetch_file`** keeps its schema and still works; it is idempotent with auto-save: a file already saved and still in the Inbox folder is answered from the record without a second download or copy. (7) **Policy form:** one new key, `files.autoSave`; a stored policy signed before D-142 without it stays valid and is read with the auto-save defaults (the one key that may be absent); every new `policy.set` carries it. An invalid policy turns auto-save off (fail closed, 06 §3). (8) **Upgrade:** agents that update start auto-saving files that arrive from then on, never files that arrived before; the app says so in a notice that stays until dismissed. Never while the agent is paused (06 §6, D-143, specified in PR #721 on wave-4; `agentlink_fetch_file` refuses with `AGENT_PAUSED`). (9) **Owner questions, decided by Tali in chat, 2026-10-30 (Decision 51, "All as recommended"; 04 §4.1):** `.download` also for macOS `.webloc`/`.inetloc`/`.fileloc`/`.command`/`.tool`/`.terminal` and Windows `.exe`/`.scr`/`.pif`/`.bat`/`.cmd`/`.ps1`/`.vbs`/`.js`/`.hta`/`.msi`/`.website`/`.settingcontent-ms`; limits 50 files/500 MB per contact per day, 200 files/2 GB per agent per day, 1 GiB free-space reserve; pre-D-142 policies read as auto-save on, with the one-time notice persisting until dismissed; Linux without a quarantine mark an accepted residual for 0.4.6; `agentlink_fetch_file` not bounded by the auto-save limits (unchanged); default folder `~/AgentLink/Inbox`; a file over a limit waits for the owner's Save. Residuals in 04 §4.1: a contact can now make bytes land on disk without a gesture (bounded by the limits), and, for files on the sender's own storage, learn when the recipient's agent is online and its IP address. Spec: 04 §4, §4.1, §7; 06 §2.3, §3; 08 §1; 11 §5.7.
