## Decision

**Invite compression: raw DEFLATE (G-12).** **Decided by Tali in chat, 2026-10-14** ("G-12: yes, raw DEFLATE (deflate-raw)"): the invite payload (04 §3.6) is compressed with raw DEFLATE (RFC 1951), with no zlib header or checksum, through the platform `CompressionStream("deflate-raw")` and `DecompressionStream("deflate-raw")` in browsers, Node and Workers, so no dependency is added. *Rationale* (the orchestrator's recommendation, which the owner accepted): the smallest option for data carried in a link, and the payload is already signed, so a zlib checksum adds nothing. **Derived (author; owner confirms at merge; the bounds and rules confirmed by the owner in D-71 (3): the 21 846-character payload limit, the 16 384-byte inflate cap, the trailing-byte refusal, the whitespace rule, the link form, the 256-code-point name limit and the bare-`0x` label):** *precision on the rationale:* the signatures cover the card and, through `nameHash` and `relaysHash`, the name and relays; `inviteId`, `secret` and `codeCommit` are not signed, but a change to any of them makes the handshake proof or A's invite check fail; `expiresAt` is not signed, so B's expiry check is advisory and A enforces its stored expiry; `v` is a schema literal and the link carries no algorithm choice; a checksum is not an authenticator, since whoever edits a link can recompute it; residual: accidental corruption of an unsigned field is caught late, at A's proof check after B's owner approved (a usability cost, not a security one); *decoder rules* (04 §3.6): the whole input bounded before any URL parsing, as the canonical link prefix plus a payload of at most 21 846 characters of strict base64url, or the bare payload; inflation in bounded slices with a running output count, capped at **16 384 bytes** before any parse (a deflate bomb), with an orderly shutdown and no operation left pending; the DEFLATE stream must end exactly at the end of the input, so malformed, truncated and trailing-byte streams are refused in every runtime, with the codec detecting trailing input itself where the platform does not; fatal UTF-8 with the BOM kept, I-JSON and the strict invite schema before Accept step 1; the encoder refuses an invite over 16 384 bytes of JSON or 21 846 payload characters; an implementation note gives the tested methods (slices of at most 1 KiB, drain before abort; re-inflating the input without its last byte must fail); *related bounds:* a link on any other host, scheme or path is refused; RFC 8259 whitespace in the inflated JSON is accepted and counts toward the cap, and the encoder writes none; the display `name` is at most 256 code points (04 §3.4, previously a `@agentlink/types` bound only); a bare `0x` relay label counts as numeric (04 §4); *not canonical:* compressed bytes are never hashed, signed or compared, and tests check decoding and round trips, never encoder output bytes; *one codec* in `@agentlink/core` (M1-7c). G-12's other half (JCS) was closed by M1-1a (4thtech/agentlink#27): in-repo RFC 8785 code checked against the RFC vectors, the alternative G-12 proposed, with no dependency
