## Decision

**Send-by-content: the AI sends a small text file it wrote, saved first into the ID's own Send folder; the Send folder and Inbox shown in Get started and on Home (FILES-SPEC-055, release 0.5.5; amends D-150 (2) "not an MCP tool … so no AI can call it" for the Send-folder writer only).** **Decided by Tali in chat, 2026-11-14:** (a) Skip on the new Files step keeps the default Send folder allowed; (b) files from the AI are saved in the root of the Send folder; (c) the AI-side texts may name the Send folder path; (d) a budget of 50 files and 64 MiB per ID per day. Purpose: a file the AI made in a chat, an artifact or a cloud workspace can be sent although the AI cannot reach any folder on the computer. (1) **`agentlink_send` takes `file: {name, content}`** (06 §2.3 "Send by content"): exactly one of `path` and `file`; `.md`, `.markdown`, `.txt` and `.json` only, valid UTF-8 without NUL, at most 8 MiB (the in-app Attach cap, D-150 (1)). A `name` with a folder part (`/` or `\`) is refused, never shortened to its last part; otherwise it goes through core's `sanitizeFileName` and the Attach type allowlist on the last extension. (2) **One writer, one place.** The content is written by the audited Attach writer (`writeSendFolderFile`, D-150 (3)) directly into the root of the ID's own Send folder (D-121 D6), only while that folder is allowed and pinned (04 §4); another allowed folder is never written to, and nothing in the call (name, content, contact) chooses or changes the folder. Exclusive create, no link followed, mode 0600, never an overwrite (`notes (2).md`); the written file must pass the full 04 §4 check; then the ordinary send under the policy in force, so every `path` rule applies again, of the bytes already in memory (never re-read from the folder). A sent or queued message keeps the file; any other ending removes it at once, as Attach does. `agentlink_send` has no pre-send approval in 0.5.5. With `notarize`, `pending_approval` and `needs_credits` concern only the proof: the message is already sent and the file stays. The digest binding, card re-hash and deny/expiry removal apply only if a pre-send file approval is added later (new card FILES-SEND-APPROVAL). A crash between the write and the stored message can leave an unsent file in the Send folder; its reservation stays counted (FILES-AI-1 review r1). (3) **Budget:** at most 50 files and 64 MiB written by content per ID in any rolling 24 hours, counted at each write (one atomic check and reservation before the write; a removed file still counts); a call that would cross either limit writes and sends nothing (`FILE_BUDGET`). The budget is fixed in 0.5.5, kept in the local store as times and byte counts only, and no MCP tool reads or changes it (I-4). (4) **No new authority (I-4).** The tool adds, widens or picks no folder, signs nothing, needs no presence and bypasses no approval: the owner allowed the Send folder with Touch ID, and the AI can already send the same bytes as `text` to the same contact under the same rules (D-70). New are only a file name and type the contact sees and a copy at rest in the owner's Send folder, bounded by the type allowlist, the size cap and the budget. (5) **Inbound content is never used (I-5, I-7).** `name` and `content` come from the calling AI's own arguments; no input takes an envelope, a received file or a path from inbound content. Neither is ever logged or put into a summary, `nextStep` or error, except the sanitised saved name, quoted as §2.1 names are (“…”). Refusals are fixed codes. (6) **Zero access unchanged.** The file then travels only the end-to-end path of any file (inline, or `ALF1` ciphertext to the drop or own storage, 04 §4); nothing new reaches a 4thTech service. (7) **AI-side texts** (06 §2.3, 11 §5.7): when no folder is allowed, the file is outside the allowed folders or not found on this computer, the fixed `nextStep` points to send-by-content for a text file and to the app to allow or use the Send folder, and may name the Send folder as `{sendFolder}` (the ID's own pinned Send folder with home as `~`; never another folder, never a path from the call). (8) **App** (08 §1, 11 §5.7): the Connect step says "Your AI may send files from ~/AgentLink/Send" above the one Touch ID (D-140 unchanged); a new **Files** step in Get started and New ID (Send and Inbox, Show in Finder, Choose another folder, Skip for now); a **Files** panel on Home replaces the Send folder banner; the Settings › Files explainer points to Attach. Numbering: OWNER-START-OVER may take a D number on a parallel branch; integration may renumber. **Threat note (author):** the new risk is an MCP-reachable write into one owner-allowed folder; a looping or injected AI can fill it only up to the budget, cannot name another place, cannot overwrite or follow a link, and cannot write a type the shell runs.
