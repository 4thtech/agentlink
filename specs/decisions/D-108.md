## Decision

**Network fields, drop-delete epoch, `agentlink verify` and the status output.** **Decided by Tali in chat, 2026-10-19:** "A A A A A: network fields under advanced; record and use the upload epoch for drop deletes; verify exit codes 0/3/1/4/2; verify reads only the proofs and inbox folders (D-87); drop the unbuilt chains line from the status spec. Record as D-108." (1) Network fields in tool results sit under `advanced` (`advanced.chain`), never top level, and no default text names a network (M1-26-b; 06 §2.4). (2) The drop adapter records the KeyStore epoch an object was uploaded under (`keyEpoch`) and signs its delete with that epoch (M1-1g-g; 07 §5.1, §5.4). (3) `agentlink verify` exits 0 verified, 3 record only, 1 does not check out, 4 not checked, 2 usage (M1-9h; 06 §8). (4) `agentlink verify` reads a pack only inside the proofs and inbox folders, as `agentlink_verify_proof_pack` does (D-87); a relative path resolves from the current folder and must still resolve inside them (06 §8). (5) The unbuilt `chains` field is removed from the `agentlink_status` output (06 §2.1). Spec: 06 §2.1, §2.4, §8; 07 §5.1, §5.4.
