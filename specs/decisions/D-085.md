# D-85: G-27: inline packing is bounded by the payload cap

- **Status:** Decided (owner, 18 Oct 2026)
- **Date:** 2026-10-18
- **Specs:** 04, 06, 07
- **Index:** [all decisions](README.md)

## Decision

**G-27: inline packing is bounded by the payload cap.** **Decided by Tali in chat, 2026-10-18 (option a).** The backlog's "inline only if the final envelope ≤ 24 KB" is not sufficient: receivers cap `aead.ct` at 17 152 B (payload ≤ 17 136 B, 04 §3.1.1) whatever the envelope size. A file goes inline only if its ALF1 ciphertext is ≤ 12 288 B and the serialized payload stays ≤ 17 136 B; the core marks eligible files inline, moves the largest inline file (highest index on a tie) to storage until the payload fits, and returns `rejected` `PAYLOAD_TOO_LARGE` (nothing sent, uploads deleted) if it still does not. Spec in 04 §3.4, pointers in 06 §2.3 and 07 §5.6.
