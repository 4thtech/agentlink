## Decision

**Owner decisions of 15 Oct 2026 on the M1-9 decomposition (the Talk part of M1a).** Decided by Tali in chat, 2026-10-15, accepting the orchestrator's nine recommendations on the M1-9 plan. (1) **Tool handlers live in `apps/cli` for M1a (G-15),** extracted to a package later. (2) **M1-7k is its own S2 card:** the core send pipeline (`sendMessage`, the `Transport` adapter and the outbox persistence), beside M1-7h. (3) **The CLI applies owner-signed decisions through core on the shared SQLite store;** core verifies the owner signature (I-4). (4) **No headless dogfood for M1a,** so M1-8f (the passphrase-locked file KeyStore) is not on the M1a path. (5) **M1-7j (owner card update, relay changes) moves to M1b,** and with it `relays set` (M1-9n). (6) **The dogfood installs from a CI-built tarball artifact:** no npm `next` or `latest` release is needed for J9. (7) **`init` writes the Codex config the same way as the other harnesses:** it shows the exact diff of the Codex config file and writes only after confirmation; it does not shell out to `codex mcp add`. (8) **The J9 dogfood starts as soon as send and inbox work,** before J8 (the terms chain) is ready; the M1a gate still needs both. (9) **e2e runs in GitHub CI with an Anthropic and an OpenAI API key as repository secrets that Tali adds himself;** agents never handle the keys (resolves the M1-13a decision). **Derived (author; proposed, owner confirms at merge):** for (1), the handlers sit in `apps/cli/src/tools/` as a runtime-agnostic module (no `node:*` and no `@agentlink/node` imports, fenced by an ESLint `no-restricted-imports` rule), extracted at M2-3b, with no new package and no new audit-rules path row now; for (3), the owner's CLI process signs and applies the decision through its own client, and the MCP server's M1a approval channel only reads and returns a ticket with no URL; for (6), M1-16 stays on the M1 gate path, not on J9; for (9), the LLM-driven variant runs only on a schedule or by manual dispatch, never in a pull-request workflow; the card split in `docs/process/backlog.md` (M1-7k, M1-9j to M1-9r and the narrowed M1-9a, M1-9b, M1-9c); a fetch-only catch-up entry point in core for the read-only `agentlink_status` (M1-7h); a single active publisher per agent (a lease row or the inter-process lock decides which process runs the outbox worker and the subscriptions); `owner init` and `contacts --verify` move from M1-9a to the S2 owner cards; the tarball job itself is a workflow change (sensitive path, owner "merge").
