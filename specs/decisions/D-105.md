# D-105: M1-4d-c: a receipt link that does not confirm is a non-fatal warning

- **Status:** Decided (owner, 19 Oct 2026)
- **Date:** 2026-10-19
- **Specs:** 05, 07, 11
- **Index:** [all decisions](README.md)

## Decision

**M1-4d-c: a receipt link that does not confirm is a non-fatal warning.** **Decided by Tali in chat, 2026-10-19:** "receipt txHash mismatch stays a non-fatal warning". When a receipt's `txHash` names a transaction that does not record that receipt, the verifier reports the non-fatal code `receipt_tx_mismatch` next to an unchanged verdict: the receipt itself stands on the on-chain record read (`getRecord`, 05 §3.3). An unconfirmed hash is never shown as a link. User wording (11 §5): "The proof's link for a receipt does not lead to that receipt. The receipt itself is on the proof network." Spec: 07 §8; 11 §6.4.
