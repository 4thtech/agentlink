## Decision

**The design has existed since 14 Oct: UI is built styled from it now, after an adjustment pass (build-plan deviation).** **Announced by Tali in chat, 2026-10-21:** "Please write in the build plan because this was built from the beginning And for some reason we did not know that it existed". **And, the same day:** "The design must be adjusted. It was built before we fine-tuned everything." (1) **What exists.** The owner's Claude Design export (D1 and a first pass of D2, with the brand) was ingested on 14 Oct 2026 (DESIGN-D1, #33) and is in `project/design/` (`d1/`, `d2/`, `brand/`): tokens (CSS and DTCG JSON), 31 component specs with a reference bundle, voice and vocabulary, a contrast table, Geist fonts, and 46 screens with PNGs (local UI, approval and commitment cards, console, desktop, verify, proof detail, printed record, invite landing, browser accept, onboarding, pay, pricing, cloud). D3 (marketing site) is not present. (2) **Deviation.** UI work no longer waits for D2: D2 is **first pass landed**, and the surfaces it covers are built **styled** from it, not functional and unstyled. Desktop stays M2 (D-31…D-41). (3) **Adjust first.** The design predates later decisions, so it is the visual basis but is **adjusted** before or while each surface is built. Card DESIGN-ADJ-1 compares every screen, string and component spec with the current specs (06, 07, 08, 11 §5 and §5.6, 12) and D-56 onward (notably D-96…D-115: D-109 receipts off by default and the proof privacy disclosure, D-111…D-114 top-up direction, free messages, top-up link and receipt payer, D-115 backup and restore; networks only under Advanced and the funded network chosen automatically, D-39, D-40; the pay page gated off until it ships). *Orchestrator plan, not the owner's words:* each finding is either fixed by agents in code (copy, small flow changes) or redesigned by the owner in Claude Design (layout, new screens); UI build cards depend on DESIGN-ADJ-1, `packages/ui` tokens and fonts start in parallel, and the build runs in the waves listed in the backlog (§3, Design deliveries). (4) **Production rules.** The `.dc.html` screens and `support.js` are preview only and never ship; production is rebuilt in TypeScript with classes, since the 08 §4 CSP forbids inline styles; the Lucide ISC notice ships with any Lucide path. (5) **Known gaps** (`project/design/README.md`): no clickable prototypes or rationale notes; light and increased-contrast themes sparse; verify shows the valid result only; open questions Q2, Q6, Q8 not shown; D3 missing. Known copy issues: the pay screen names a network in the default view (D-40, 11 §5); verify and proof detail show raw `0x…` record IDs in the default view; `strings.en.json` needs a full 11 §5 audit. (6) **One status.** The design status lives only in `project/design/README.md`, and session start checks it (LL-16). Spec: 10 "Design deliveries", M1-11, M2-1; 11 §5, §11.7; 08 §4.
