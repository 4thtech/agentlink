# @4thtech-io/types

## 0.1.0

### Minor Changes

- 1feb21c: **Breaking (unreleased envelope format): key commitment and CEK-derived wraps (G-46, D-66).** The payload AEAD no longer uses the content key (CEK) as its key. `encKey` (`agentlink/v1/payload-key`) and a 32-byte key commitment `kc` (`agentlink/v1/payload-commit`) are derived from the CEK with HKDF-SHA256, and `aead` is now exactly `{alg: "A256GCM-KC", iv, kc, ct}`. The parser and `@agentlink/types`' `aeadSchema` refuse the earlier `A256GCM` form and any `kc` that is not exactly 32 bytes. `decryptPayload` compares `kc` in constant time before AES-GCM and reports a mismatch as the same `open_failed` as a failed tag. The new `checkKeyCommitment(envelope, cek)` lets the core tell the two apart. `wrapCek` is now deterministic: each entry's ephemeral X25519 key is derived from the CEK, the envelope id and the recipient key (`agentlink/v1/cek-eph`) and passed to `@hpke/core` as an imported key pair, never through `DeriveKeyPair`. The new `checkWrap(pk, id, cek, entry)` recomputes one entry from a public key and the CEK and compares it byte for byte. Derived keys are wiped after use. New exports: `checkWrap`, `checkKeyCommitment`, `KEY_COMMITMENT_LENGTH`, `PAYLOAD_KEY_LABEL`, `PAYLOAD_COMMIT_LABEL` and `CEK_EPH_LABEL`. The worst-case envelope grows from 24 509 to 24 563 bytes, still under the 24 576-byte limit.
- 39b1d8c: Add the `terms` schema of 04 §3.4 with the D-74 canonical form: every key always present (`price: null` when none), `parties` in ascending byte order, the character rule on a pinned UCD 15.0.0 table (`refusedCategory15`; Cc, Cf, Zl, Zp, Co, Cs and Cn refused, and NFC) with the Unicode 15 runtime probe (`isTermsRuntimeSupported`, `UNSUPPORTED_RUNTIME`), the D-74 size limits (`TERMS_LIMITS`), currencies by grammar or `USDC`/`USDT`/`XDAI`, and a checked `note`. `TermsInput` (`termsInputSchema`, `parseTermsInput`, `termsInputJsonSchema`, `termsFromInput`) and the pure negotiation-chain reducer (`receiveTerms`, `recordSentTerms`, `nextTermsLink`, `checkSendAccept`, `negotiationKey`, `EMPTY_NEGOTIATION`). In `@agentlink/crypto`: `termsHash` (sha256 of the JCS form, bare hex) and `verifyTermsHash`. **BREAKING:** `offer`, `accept` and `reject` bodies and the commitment approval context now require strict canonical `terms`, and the terms tools' approval `args.terms` must be a strict `TermsInput`; the body `note` is at most 500 code points of canonical text; `hasControlOrFormat` (summaries, `nextStep`) now uses the UCD 15.0.0 table; `isUtcTimestamp` moved from the proof module to the encodings module (same export name).
- 427592d: Add the per-path decoders of 04 §2.4.1: `decodeAtPath` decodes a value by its schema path (never by field name) and returns its bytes, or null for any non-canonical form; `equalAtPaths` compares two encoded values as bytes, each decoded by its own path; `ENCODING_PATHS` and `isEncodingPath` list the table. **BREAKING:** the `files[].inline` cap is now the spec's 12 288 bytes of ALF1 ciphertext (16 384 base64url characters, 04 §3.1.1), so `MAX_INLINE_CIPHERTEXT_BYTES` is 12 288 and `MAX_INLINE_FILE_BYTES` (inline plaintext) is 12 255; a longer inline value is rejected.
- e6a146d: Add the protocol constants and strict schemas for messages, message contents, owner-signed actions, agent cards and invites; anything malformed or not in its exact canonical form is rejected.
- a71148b: Add the strict policy schema with the exact default settings and per-contact proof rules, exact USD amount handling, the approval details for each tool, the proof pack and proof status formats, the common tool-result shape, and the timing limits for owner actions and approvals.
- 7470286: Pairing bodies carry the safety-code fields: the invite adds `cardAgentSig` and `codeCommit`, the `handshake` adds `cardAgentSig`, `codeNonce`, `codeCommit` and `inviterCardHash`, and the `handshake-ack` adds `handshakeHash`, `codeReveal`, the inviter's `card` and `cardSig`, and its `relays`. All are required. A relay list carried with a card now needs 2 to 16 relays.
- 667dc38: Add the `approval.decideBatch` owner action: one owner signature over 2 to 20 approval decisions, each exactly an `approval.decide`, in strictly ascending `approvalId` byte order with no duplicates; anything else is rejected, never sorted. Adds the batch item bounds, its maximum lifetime and the 600-second local expiry as constants, and the `approval` envelope now carries a batch.
- 9722c8a: Add the `contact.check` owner action (G-28): the owner's signed statement that they compared the safety code with a contact, binding exactly the contact's agent ID and the pairing's transcript digest, each in its one canonical encoding; any other spelling, an unknown key or another op's params is rejected, never normalised. Adds it to `OWNER_ACTION_OPS` and the owner-action union, with a typed signed wrapper.
- 66e997c: Add `ApprovalService.read(approvalId)` and `ApprovalService.countPending()` in `@agentlink/core` (M1-7e-3): one approval's state for its own stored action, with the stored owner decision and cancel re-verified against the recomputed action digest before the status cache is read (`pending`, `approved`, `denied`, `cancelled`, `expired`, `used`, `void`, or `unknown` with `not_found` or `invalid` for a row that does not verify), and the number of approvals waiting for the owner. The result never carries the owner signature, the decision payload, the action or the summary, and reading never changes a row. `OwnerActions.readApproval` backs it. In `@agentlink/types`, a `pending_approval` result no longer requires `url` (06 §2.5: none in M1a), and `getApprovalResultSchema` accepts `used: true` on an `expired` approval.
- a1465a6: Wire `agentlink_get_approval` and the `pendingApprovals` count of `agentlink_status` to the core approval read (M1-9c-b). Every request from an unknown sender now carries its sender code from core (`RequestEntry.senderCode`, and the code on an inbox request item): the short form, or the extended form when two unknown senders share the short form (04 §2.9). `agentlink requests` shows it. `@agentlink/types` adds `toolResultCommonSchema`, the one rule set for the common tool-result fields.

### Patch Changes

- d8228d2: The pinned UCD 15.0.0 character table behind the `terms` character rule (`refusedCategory15`) is now generated from the vendored, SHA-256-pinned UCD file `DerivedGeneralCategory.txt` instead of the interpreter's Unicode data (D-74, D-77). Its content is unchanged: no code point is categorised differently. Only the generated file's provenance comment changes.
- 810e746: Download URLs in file entries now need a lower-case host and a port between 1 and 65535, as relay URLs already do. The package tests now run in Node, Chromium, Firefox, WebKit and Cloudflare Workers.
