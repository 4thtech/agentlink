- Native notifications in the desktop app (N7, S2, PLAN-NOTIFY §3.5, D2; proposed, owner confirms at merge). The core sends only fixed codes over the app's private pipe, `notify {kind, count, name}` with the kinds approvals, messages, files and update; the pipe refuses any other key, kind or name shape, so no message text, file name or link can travel. The app's main process shows an Electron notification (the AgentLink name and icon, no longer "Script Editor") with fixed words: "Approval waiting", "New message", "File received", "Update ready". At most one per kind every 30 seconds; what arrives meanwhile is counted into one later notification. A click brings the window forward and opens one fixed page per kind (Home for approvals, messages and files; Settings › Updates for an update); no notification approves, accepts or replies. The dock badge is the number of approvals waiting. On Windows the app sets its AppUserModelID (`4thTech.AgentLink`) at startup, and the installer sets it on the Start menu shortcut. An approval is noticed by its own ID, so one decided and another raised in the same few seconds still alerts.
- While the desktop app runs it owns the notifications for the ID it has open: its core writes `~/.agentlink/desktop-alerts.json` (0600: its process ID, start time, last write and that ID; renewed every minute) and `agentlink mcp` for that ID then shows no osascript or notify-send alert, so there are never two. Every other ID keeps today's alert. A record that is not renewed for 3 minutes, or is from before the computer started, no longer counts. The browser and terminal app keep today's alert and its switch. On Windows the installer sets the same AppUserModelID on the Start menu shortcut.
- Settings › Notifications shows only the switches that work where you are. In the desktop app: Approvals waiting (on), New messages, Files received, Updates and Show names in notifications (off). Show names uses only a name you gave the contact on People; a name a contact chose for themselves is never shown. In a browser: Approvals waiting, as before.
