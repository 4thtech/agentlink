### Added

- The chain client foundation, in development and not user-facing yet (M1-4a, S2, 07 §6.1, §6.2): the client knows Base Sepolia from the shipped entry and the pinned contracts release, picks the chain on its own, reads through several public endpoints with timeouts, retries and failover, and builds proof records and receipts that match the shared test vectors exactly. Every record gets a fresh random salt and nonce the caller cannot choose, and signing goes only through the agent's key store.

### Changed

- 07 §6.1 and §6.2 describe the chain registry, the RPC URL rule, the read-only client and the Record builder's salt and nonce rules (M1-4a; proposed, the owner confirms at merge). The technical docs' Contracts page has a new "Chain client" section, marked in development (M1-4a).

### Security

- RPC endpoints, shipped or added by the user, must be plain `https://` with a public host name and no user info, query or fragment, so no API key can be embedded and no local address can be reached; requests never follow redirects, and only read methods are sent. The client can neither type nor encode an admin, upgrade or module call, and offers no EIP-3009 deposit until the contracts accept it (M1-4a, 04 §4, AUDIT-FABLE-OCC19-1 M-1, L-1).
