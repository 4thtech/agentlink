# Changelog

All notable changes to AgentLink are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). How versions, tags and releases work is described in [`docs/process/versioning.md`](docs/process/versioning.md). Until 1.0.0 (the M3 mainnet beta), a minor version may contain breaking changes; each is marked **BREAKING:**.

## [Unreleased]

### Added

- Security utilities for files (M1-15, S1, 04 §4, §7; not wired into any tool yet, M1-7f and M1-9d use them): `@agentlink/core` gets the pure checks (`checkFetchUrl` on the raw URL string: `https` only, no numeric host notation in any base, no local or internal names, no user info; `pickPublicAddress`: every resolved address must be globally routable; `decidePath` for both POSIX and Windows paths; `sanitizeFileName`). `@agentlink/node` gets `nodeSafeFetch` (one lookup per hop, connect to the checked address, at most 2 redirects each re-checked, byte cap, one deadline, no proxy; errors never carry the URL), `resolveAllowedFile` / `openAllowedFile` (realpath on both sides; hidden files, `~/.ssh`, `~/.agentlink` and keychain folders always refused, also through links) and `createInboxFile` (sanitised name, exclusive create, never through a link). In Workers (G-14, proposed) the raw URL check applies and the address check relies on Workers egress; that path lands with M2-3b.
- Crypto (M1-1j, S2): EIP-712 typed data and hashing for the OCC v2 proof types `Record`, `Receipt` and `Registration` under the chain domain `{name: "OCC", version: "2", chainId, verifyingContract}`, with strict 05 §3.1 JSON-form parsing (refused, never normalised); `recordStructHash`; the recipient commitment `keccak256(abi.encode(recipientAgentEvm, salt))`; and EIP-3009 `ReceiveWithAuthorization` typed data under a token domain the caller reads from chain. The `eip712-proof` vector suite is no longer pending. The revoke struct waits for G-20 (M1-1i-b).
- Storage (M1-6a, S2): `@agentlink/storage` has the `StorageAdapter` interface (07 §5.1), the inline adapter (ciphertext up to 12 288 bytes, base64url in the payload) and the S3-compatible adapter over `aws4fetch`: upload, a presigned download link clamped to 7 days and to the expiry of temporary credentials, and delete. Objects are keyed `agentlink/<storagePrefix>/<random>` with no metadata; credentials come from an injected provider; no credential, link or object key is logged. Not yet wired into the tools; integration tests against MinIO and R2 follow in M1-6a-2.
- Local approval server (M1-8d, S2, `@agentlink/node`; not wired into the CLI yet, M1-11a): an HTTP server on `127.0.0.1` and a random port with a view-only session token kept in memory (exchanged for an HttpOnly cookie, never written to disk or logged), exact `Host` and `Origin` checks against DNS rebinding, a CSRF token and non-simple requests for decisions, and owner presence (owner code or owner passphrase) for every approve or deny, signed as one `approval.decide` that core verifies. Each approval ID is decided once through it; a fixed OS notification and the `/approve/<id>` route are included. The same-user script test runs against the live server.
- Live relay subscriptions (M1-9s): while `agentlink mcp` runs and holds the publisher lease, new messages and handshakes are stored and processed as they reach a relay instead of on the next 30 s poll. The core `Transport` gains `subscribe` and the client `subscribeInbox` (same receive path as `syncInbox`: dedup by gift-wrap ID and envelopeHash, one store transaction, rate limit). The background loop keeps a catch-up every 5 min as a fallback, polls when no subscription can open, and closes the subscription on lease loss and on shutdown.
- Spec text sync (M1-9s): the 07 §4.1 interface sketch now shows `subscribe` with the implemented `sync` handler shape (relays, identities, persistence, onEnvelope) and an unsubscribe that resolves once in-flight handlers settle; no protocol change.
- Dogfood tooling (M1-23-b): `tools/dogfood/run.mjs --role a|b` runs the pairing, messages, owner approvals and the J8 negotiation across two Macs, one agent per Mac, with the invite link and run ID exchanged by hand; `--same-owner` for one person at both Macs. Single-machine mode is unchanged. Runbook RB-17 section 10 has the commands.
- Test vectors (M1-1i, S2): two new suites, pending until their code lands. `eip712-proof` (M1-1j) covers EIP-712 hashing of `Record`, `Receipt` and `Registration` under the OCC v2 chain domain, the recipient commitment, and the `Record`/`Receipt` JSON-form rejections. `prf-wrap` (M1-1k) covers the passkey PRF salt and wrap key (04 §2.3). STREAM and revoke vectors wait for G-26 and G-20 (new card M1-1i-b).
- CLI (M1-9w, S1): `agentlink init --harness claude-desktop` sets up the Claude desktop app (macOS and Windows; its own `claude_desktop_config.json`, not Claude Code's file), with the usual diff, confirmation, backup and refusal of malformed files. On Linux it says the app isn't available there.

### Fixed

- CLI (M1-9w, S1): Gemini CLI is detected by the `gemini` program or `~/.gemini/settings.json`, so a computer with only Antigravity's `~/.gemini/config/mcp_config.json` is offered Antigravity, not Gemini CLI.
- `agentlink owner add-agent --agent <name>` (M1-9x, S2): when an owner is set up on this computer but no agent has a card from it (for example after every agent was removed), it no longer dead-ends between `owner init` and `owner add-agent`. Your owner code unlocks the saved owner, you confirm the owner fingerprint, and the agent gets its card. Same rules as before: your own terminal only, refused inside an AI app, the owner key is never changed.
- Spec 04 §2.8 (M1-9x, S2, proposed, owner confirms at merge): new rule "No local card names the owner" (owner keys derived from the unlocked owner item, fingerprint confirmed before the one card is signed, a consistency check, not authentication); "Expected owner" names this case.

### Changed

- Spec (G-26, G-20, S2, D-80, D-81): ALF1 file encryption now binds the 17-byte header into every chunk's AAD (`header ‖ u8(isFinal)`, 04 §4), so a changed header fails decryption. OCCRegistry gets an owner-signed EIP-712 `Revocation` struct with single-use owner nonces shared with `Registration`, an epoch check, and revoke while paused (05 §4). Spec only; no code change.
- CLI (M1-22-b, S1): `agentlink_inbox` offers carry a `termsParties` field naming the agents in their terms as "you", a contact's name (06 §2.1 rule) or null, so summaries need no raw addresses; with `openOffers: true`, identical offers from one contact (same terms hash) add one hint line ("<name> sent the same offer N times; reply once."). The offers themselves are unchanged. Spec: 06 §2.2 documents `termsParties`.
- Core (M1-7i, S2): the policy engine applies the remaining 06 §3 rules. Files: a send needs an owner-allowed folder (none by default, so the tool asks for setup), stays within `maxSendSizeMB`, and goes inline, to the encrypted drop or to own storage per `files.storage` (D-48); a received file stays within `maxReceiveSizeMB`. Proofs: `notarize`, `perActionMaxUSD` and `dailyBudgetUSD` over a rolling 24 h window (G-7), with per-contact rules (G-32) in the 06 §3 steps. The budget check and the reservation of the maximum fee run in one store transaction, a reservation is released only after its deadline with no record on-chain, and a missing, inconsistent or clock-skewed ledger makes every paid proof ask the owner until the next owner-signed policy. Under an invalid policy, sending a file is refused (no folder is allowed) and fetching one needs the owner.
- CI (M1-9c-c, S2, process): new `bundle-check` job in `ci-gate`. It builds the CLI on a runner with no keychain and no native-module build and fails when the published `dist/agentlink.js` imports a crypto-capable MCP SDK transitive package (`jose`, `pkce-challenge`, `cookie-signature`, `etag`, `hono`), an SDK subpath outside the stdio set or an undeclared package, or when `src/tools/` bundled for a neutral (Worker) platform reaches a Node built-in, `@agentlink/node` or the MCP SDK (IR-M1-9c-1 F07, D-76, 06 §1). No new dependency: it reuses the repository's Vite. `docs/process/ci-cd.md` records it.

- Spec (M1-9v, S1, 06 §4): the untrusted-content wrapper spec now says that every opening and closing `untrusted_content` tag inside content is escaped, look-alike forms included, as the code already does. No behaviour change.
- `agentlink_propose_terms` and `agentlink_respond_to_terms` now pass `clientRequestId` to the core (M1-32-c, S1): a repeated call returns the original result and sends nothing more; a different request under the same key is `IDEMPOTENCY_KEY_REUSED`, a concurrent repeat is `IN_PROGRESS` (as `agentlink_send`), and a repeat whose approval has since been decided reports that approval's state.
- CLI: an agent that has no card from its owner yet is now told so. `agentlink_status`, the other tools and `agentlink doctor` say to run `agentlink owner add-agent --agent <name>` in your own terminal instead of suggesting `init` (M1-9u). `owner add-agent` also explains the case where an owner exists but no agent here is attached to it.
- OPS-REL-3: the "Version packages" PR now rolls `CHANGELOG.md` `[Unreleased]` into the version section (`tools/release/roll-changelog.mjs`), and a GitHub Release body over 125,000 characters falls back to a short note with a link.
- CI (OPS-CI-4, S2, process): new `sync-pin` job in `security.yml` (push to `main`, weekly) fails when the secret-scan stub on the `sync` branch is pinned to a commit older than the last change to `secret-scan.yml` or `.gitleaks.toml` on `main`; `sync-protocol.md` and `ci-cd.md` document the re-pin procedure.
- Process (owner decision, 2026-10-17): open question G-14 (`agentlink_fetch_file` and SSRF in Workers) blocks only M2-3b, not M1-15; the Workers egress part stays open.
- Docs: README, `knowledge/`, `llms.txt`, `docs-site/` and `docs/status.yaml` now say v0.1.0 is released (16 Oct 2026, `npx -y @4thtech-io/agentlink init`); the OpenCode and Antigravity quickstart, the messages, contacts, approvals, first-message and troubleshooting pages are filled in. Files, proof and the apps stay planned.

- MCP background loop (M1-9r, S1, 06 §6, D-73): while `agentlink mcp` runs, the server that holds the agent's publisher lease (taken and renewed every 20 s, released on clean shutdown, including on SIGTERM or SIGINT) syncs its relays (the first pass is the 48 h start-up look-back), processes stored envelopes (handshake completion and `handshake-ack`, acks, card updates) and runs the outbox retry worker, so an invite accepted while the inviter's server runs completes the pairing without any tool call. Other servers of the same agent stay idle, keep answering every tool, and take over once the lease lapses or is released; CLI commands never take the lease. Optional `agentlink://inbox` resource (counts only) with `notifications/resources/updated` for subscribed clients; the tools work without it. The core transport has no live subscription yet, so the holder reads its relays with a catch-up pass every 30 s; after a partial pass (offline, relays down) it retries after 1 s, doubling up to 30 s, so it never loops fast. Live subscriptions follow in M1-9s (M1b).
- MCP approvals and request sender codes (M1-9c-b, S2): `agentlink_get_approval` now reports real approval state in production, read from core with the owner's stored decision re-verified: a row that was edited, or whose stored decision no longer checks out, reads `denied` and is never `approved`; a used approval reads `expired` with `used: true`, a withdrawn one `expired`, and an unknown ID `not_found`. `agentlink_status` counts the approvals waiting for you (not used, withdrawn, decided or lapsed ones). Each request from an unknown sender now shows its sender code, computed in core: the short form, or the longer form when two unknown senders would share the short one; `agentlink requests` prints it, and never a name the sender chose. Result checks in the MCP server now use the single rule set in `@agentlink/types` (IR-M1-9c-1 F06).
