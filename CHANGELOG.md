# Changelog

All notable changes to AgentLink are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). How versions, tags and releases work is described in [`docs/process/versioning.md`](docs/process/versioning.md). Until 1.0.0 (the M3 mainnet beta), a minor version may contain breaking changes; each is marked **BREAKING:**.

## [0.4.6] - 2026-10-30

### Added

- Files you receive are saved automatically (W4-AUTO-SAVE, S2, D-142, 04 §4.1): when a contact you keep sends a file, your agent downloads it, decrypts it on your computer, checks it and saves it into your Inbox folder (default `~/AgentLink/Inbox`), with no request from you or your AI. It stays within the daily limits (50 files and 500 MB per contact, 200 files and 2 GB in total), keeps 1 GiB free on the disk, and never saves while the agent is paused or for a contact you set to "Ask before saving". Every saved file gets the system's "downloaded from the internet" mark on macOS and Windows, is never made runnable, and never replaces anything in the folder; names that the system could act on get `.download` added. A file that is not saved automatically waits for Save, with a short reason. Your AI's file fetch and Save never write a second copy of a file already saved. The app reads which files were saved automatically, why others were not, your Inbox folder, and the one-time "now saved automatically" notice; the screens show them in a follow-up.
- A received file can be saved from the app: "Save to Inbox" with one Touch ID (or the backup code) decrypts it on this computer and puts it in your Inbox folder. The app sends only which file, never a name or a path, and still never opens a file (W4-FILES-SAVE, S2, 04 §2.5.1 `file.save`, 08 §1).
- The Inbox page for the new home: "Needs you" on top (approvals as cards you confirm with Touch ID right there, new messages, files waiting to be saved), conversations per contact with messages and files inline, and "All caught up" when nothing waits. It appears in the sidebar when the new shell lands (W4-INBOX, S2, 08 §1, b11 §34.4).
- Live AI app status (W4-LIVE-STATUS, S2, D-143, 06 §6, 08 §1): the app now knows which AI app runs which agent while it runs. Each AI app's AgentLink connection reports in every 15 seconds, so an app that quits or crashes drops off within seconds, a second AI app on the same agent shows too, and each app reads as Working, Ready, Idle, Not running (with when it was last seen) or Not set up. The app gets these changes through a new live update stream on this computer only; it carries only agent names, labels, app names, states and times. The screens switch to it in a follow-up.
- The wave-4 motion kit for the local app (W4-MOTION-KIT, S0; W4 UX v2 "Motion and perceived speed", D-116): motion tokens from the approved prototype (spring curve, page change, reveal, press, pulse), page changes with View Transitions that fall back gracefully, skeletons in the shape of the real screens after 300 ms, a pulsing live dot, items you send that appear at once, and fades only when you ask for less motion. Screens adopt it in the following wave-4 cards.
- Pause an agent (W4-PAUSE, S2, D-143 (5), 04 §2.5, 06 §6, 08 §1): the app can now stop one agent in every AI app that runs it with one click, and start it again with Touch ID. While it is paused, the AI can still read what the agent already holds, but sending messages, answering offers, adding proof, invites and fetching files are refused with "This agent is paused. The owner can resume it in the AgentLink app."; messages already waiting to go stay queued and go out after resume, and nothing new is received until then. The AI cannot pause or resume an agent. The Pause button and the paused banner come with the Agents screens in a follow-up.
- Invite someone, the new way (W4-PEOPLE-INVITE, S2 by path, prototype v23 A3–A7): one screen with your short link ready to copy, email or share, a preview of what your friend sees, open invites you can cancel, and a "You and … are connected" moment on both computers with the safety code to compare. Under the hood shows the long link and a QR code.
- Settings is now one list with a line under each setting, and Advanced opens in place. Under the hood gains a live activity stream, a Relays & network page and a Diagnostics page with a copyable report; Backup & Touch ID and Notifications have honest "not yet" pages (W4-SETTINGS-ADVANCED, S1).
- Short invite links (W4-SHORT-INVITE, S2, D-139, 04 §3.6.2): a new invite link is under 80 characters. The invite is encrypted on your computer and kept on the encrypted drop until it is used, cancelled or expires (at most 7 days); 4thTech only ever holds ciphertext. If the drop can't be reached within 10 seconds, you get the long link automatically, and you can always choose the long link under Advanced or with `agentlink invite --long`. Older long links keep working.
- Open invites in the app (W4-INVITES-LIST, S2, 08 §1): Contacts lists the invites you created, with who they are for and when they expire, and a Cancel button. A lost link can't be shown again: cancel it and create a new one.
- `pnpm verify` runs the checks CI would run for the packages a change affects, in one command, and prints a short summary to paste into the PR (W4-VERIFY).

With Under the hood on, the same screen becomes a table you can search, filter by status or AI app and sort by activity, with a bulk Remove, and each agent has its own page with its AI apps, people, rules, recent activity and backup (W4-AGENTS, D-143, D-141; W4 UX v2).

It replaces the rule that files were saved only when you or your AI asked. Daily limits per contact and in total, a free-space reserve, a per-contact "Ask before saving" and a global off switch keep you in control; saved files carry the system's "downloaded" mark, are never opened or run by AgentLink, and are decrypted only on your computer. Your AI's file fetch still works and does not save a second copy. The owner decided the defaults (Decision 51): at most 50 files and 500 MB per contact and 200 files and 2 GB in total per day, 1 GiB kept free, and a file over a limit waits for you to tap Save. Below it: Invite someone, and the people your AI talks to, each with their last activity. Open a person to see the conversation both ways (each message you sent says Sent, Waiting to send or Not delivered; Copy on every message; earlier messages load on request), the files you exchanged (Save to Inbox, Show in Finder, Show in Explorer on Windows, Show in folder on Linux) and a menu to rename them, check the safety code or remove them. With Under the hood on, the same screen becomes a table with search and an agent filter, each message shows its ID, exact time, size, agent, receipt and proof, and several free requests can be approved together; anything that costs money or commits you is still approved one at a time (W4-HOME, Decisions 47–50).
- A file that arrived and is not saved now reads "Arrived · not saved" with a Save action, instead of "Not saved yet. Ask your AI to fetch it." (W4-FILES-SAVE, 11 §5.7).
- Spec for live AI-app status and Pause (W4-LIVE-STATUS, W4-PAUSE, S2, D-143; 04 §2.5, §2.5.1, §4; 06 §6; 07 §3.2; 08 §1): the app will show within about 2 seconds, with no reload, which AI app is working with which agent ("Working in Claude Code", "Ready", "Idle", "Offline · last seen 5 min ago"), and the owner will be able to pause an agent with one click, in every AI app at once, so it sends and receives nothing until resumed with Touch ID. While paused, new sends are refused and queued items wait; AI apps AgentLink does not know show as "Another AI app". Pause and these rules decided by the owner (Decision 50, 30 Oct 2026); other details proposed, owner confirms at merge.
- One Touch ID creates your agent and connects your AI app (W4-ONE-TOUCH, S2; D-140; 04 §2.8, 08 §1, 11 §5.8): on the first launch, "Connect to {app}" is ticked for the AI app you picked, and the one Touch ID that protects your approvals also creates the agent and adds AgentLink to that app ("{label} is ready in {app}. Restart {app} to finish."). "New agent" in the app works the same way. Untick it ("Not now") to connect later. If the app's settings can't be written, the agent is still ready and the app offers Connect.
- Renames reach contacts (W4-RENAME-REACHES-CONTACTS, S2, D-141, 04 §2.6): renaming an agent in the app now signs a new card with the new name in the same Touch ID, and every contact gets it with the existing card update. Your contacts see the new name, their safety codes stay checked, a contact that missed the update gets it again (at most once a day), and an agent can be renamed for its contacts 3 times a day. Agents renamed before this can "Update contacts" once. No AI app tool or terminal command can rename an agent.
- The app has a new frame. At the top: your agent with a live status ("Ready in Claude Code") and a menu that shows every agent and AI app as it changes, Go to (Cmd+K), a "?" Help menu (Get started, Keyboard shortcuts, User guide, Report a problem) and the "Under the hood" switch. On the left, a small menu (Home, Agents, Activity, Settings) that the arrow expands; on a phone it opens from the top. Under the hood adds a live status line and an Advanced group on the same screens, is remembered by the app for every window, and turns on and off with Cmd+Shift+U. Old addresses still work (W4-SHELL-V2, Decisions 49–51; 08 §1 `ui-settings`, proposed).
- Adding an agent now asks for its name first, then which AI app it works in, then one Touch ID, in the same Get started steps (from the agent menu or Agents); when it's done you can open the new agent. Got an invite link from someone? "Have an invite link? Paste it" (People, or the Invite screen) accepts it with Touch ID without making an invite of your own. The old Add agent and Add contact panels are gone (W4-WIRE-2; owner Decision 52).
- The new app now fits together: Home shows "Get started · n of 3 done" until setup is done; the last Get started step makes your invite link right there; New agent in the search menu uses the same Get started steps; every Invite someone opens the Invite screen; the "Switch to Touch ID" note goes away as soon as Touch ID is set up; the agent menu fits a phone screen; small motion touches (the Connected check, Home's row arrow) (W4-WIRE; W4 UX v2).
- Getting started is a short guided path (W4-WIZARD, W4 UX v2 layer 1): pick your AI app, confirm it's you with one Touch ID, see "Connected to {app}", then invite someone if you like. Each step shows where you are ("Step 2 of 4") and "Skip to Home". It opens by itself only until you're set up (an agent with an AI app connected); after that the app opens on Home, and Get started is always in Help, in Cmd+K and on a Home card until you hide it. Adding an agent or connecting another AI app uses the same steps.

### Fixed

- Recovery kits restore again (HOTFIX-KIT-RESTORE, S2; 04 §2.3.3, §2.4.1): restoring an agent from its recovery kit no longer fails with "cannot open" for every real agent. A kit from another owner is still refused, and nothing is written before the checks pass.
- The app now notices at once when you quit or start Claude Code, Codex or another AI app (W4-SHELL-LIVE, S2, D-143, 08 §1): no page refresh needed. The agent menu shows each AI app as Working, Ready, Idle, Not running (with when it was last seen) or Not set up, and the agent as Working in, Ready in or Offline with when it was last seen. If the live updates cannot reach the page, it checks every 5 seconds instead. The top of the page no longer jumps when Under the hood turns on or a status changes.

- A received file on Home is one light row: its name in a compact "from them" container, "Saved to ~/AgentLink/Inbox" and Show in Finder; "Saved as" shows only when the name changed. The name stays plain text inside the untrusted container, isolated from the text around it (W4-WIRE-3, 11 §5.7, I-5).

## [0.4.5] - 2026-10-29

### Added

### Changed

- Docs and status now say AgentLink 0.4.4 was released on 29 Oct 2026 (Welcome and a short first run, all your agents in one window, the AI apps page, the live connections map, Start here in seven steps, joining from an invite link, and contacts seeing the name you typed). - Spec: one Touch ID creates an agent and connects its AI app (W4-ONE-TOUCH, S2, D-140, 04 §2.8, 08 §1): the agent's keys are made before the gesture so the AI app change can name the new agent, one challenge binds the whole set of signatures, and the AI app entry is written last; if only the entry fails, the agent is kept and the app offers Connect.
- Spec: renames reach contacts (W4-RENAME-REACHES-CONTACTS, S2, D-141, 04 §2.6, 06 §6): renaming an agent in the app now signs a new card with the new name under the same Touch ID, and the existing card update tells every contact, who see "{new} (was {old})" once. ### Fixed

- The release health check waits up to 15 minutes for npm to serve each new package file before it checks provenance and signatures, and a re-run of a release that failed after publishing now finishes it (moves `latest` after the check passes, then creates the GitHub Release and the desktop bundles) instead of stopping; it finishes only on a re-run of the same run and only the exact package files that run built (CHORE-RELEASE-HEALTH-TARBALL-WAIT, process).
- A new contact now appears on both Contacts pages without a reload once an invite is accepted: the page keeps checking while one of your invites is open or you are connecting (HOTFIX-045-CONTACTS-NEW).

- Removing an agent works right after first run (HOTFIX-045-REMOVE-FIRSTRUN, S2; 04 §2.5, 06 §6): on a new computer, Remove no longer says "Couldn't finish removing" until you quit and reopen the app. Touch ID or your backup code is still asked before anything is deleted.
- Removing an agent finishes (HOTFIX-045-REMOVE, S2; 04 §2.5, 06 §6): Remove no longer stops at "Removal not finished — Try again" every time, and Try again now also works on a computer with only one agent. Touch ID or your backup code is still asked before anything is deleted.
- The top bar shows one status instead of two and no "+N" chip, and a file that arrived but is not saved shows a fixed line instead of an endless bar (HOTFIX-045-TOPBAR, S1, 08 §1).
- Touch ID instead of the backup code when no agent is open (HOTFIX-045-TOUCHID, S2; 04 §2.3.1, §2.5; 11 §5): the app now finds your Touch ID even when no agent is open. ## [0.4.4] - 2026-10-29

### Added

- The local app can hold all your agents and switch between them in the same window (U3-c, S2, D-138; 08 §1, 04 §2.5, 06 §6): every agent already on this computer is listed and nothing is renamed; switching shows the chosen agent's own contacts and messages and asks for no Touch ID, because it approves nothing. A page that was showing another agent is refreshed before it can change anything.
- Name your agent at first run, add another agent and rename one in the local app, each with one Touch ID (U3-d, S2, D-138; 08 §1, 04 §2.5.1, §2.8): adding an agent creates it, signs it and names it in one step, and if anything fails nothing is left behind; renaming changes only the name you see, never its folder, its AI app entries or its identity. Setting up never changes your AI apps' settings.
- Remove an agent in the app (U3-e, S2, D-138, 08 §1, 04 §2.5): with Touch ID and its name typed, an agent is retired for good, its contacts are told, and its keys, messages and files are deleted from this computer; your owner and your other agents stay. It is refused while an AI app still has the agent open ("Quit any AI app that uses {label} first."), and if contacts can't be told it asks before going on. A removed agent can't be restored from a backup; it can only come back as a new agent.
- Connect an AI app to your agent from the local app, move it to another agent, or disconnect it, each with one Touch ID (U3-f, S2, D-138; 08 §1, 04 §2.5, 06 §7): the app shows exactly the AgentLink entry it adds, changes or removes, and nothing else from that app's settings file, keeps a backup of the file, and never changes Claude Desktop's settings while it is open. Each AI app works with one agent at a time; the Agents list now shows which AI apps each agent works from.
- U3-flow: the local app can ask for the live connections map's metadata for the open agent (`GET /api/ui/flow?since=<cursor>`), through a new read-only core view. It never carries content, names, links, keys, hashes or envelope IDs, and has no byte progress (U3-flow, S2).
- Switch between your agents from the top bar of the local app, and see which AI app each one works from (U3-h, S1, D-138; b11 §29). The new Agents page lists every agent with its contacts and an Add agent button; each row has Switch, Rename, Connect an AI app and Remove. Remove names what goes, asks you to type the agent's name and offers "Export history first". A calm "Tidy up" note on Home points to leftover test agents.
- AI apps page in the local app (U3-i, S1, b11 §30): see which AI apps AgentLink found and which agent each works with, then connect one, move it to another agent or disconnect it. You see the exact entry that will be added first, then confirm with Touch ID; a backup of the file is saved first and nothing else in it changes. Claude Desktop must be closed first.
- A friend without AgentLink can join from an invite link in one step (U3-invite, S2, owner decisions 30 and 32; 08 §4, 06 §8, b11 §33): the invite page says "{name} invites you to connect your AI agents. Takes about 2 minutes." and offers one command for Terminal (`npx -y @4thtech-io/agentlink join '<link>'`) or one sentence for their own AI, with a "Need Node.js? Get it here" link to nodejs.org. The command opens the AgentLink app, runs setup and ends on "Accept {name}'s invite? Check it's {name}: {fingerprint}"; accepting needs Touch ID, and the safety code comes after connecting. The invite stays in the link's `#` part, read only in the browser, and is held only in the app's memory on the computer; the page, `join` and the app accept only the exact AgentLink link form, so nothing in it can run as a shell command.
- A small calm mark on a conversation or file that is moving right now (U3-map-2, S1; b11 §32; owner decision 8). In Messages, a row shows "Sending" or "Receiving" with a short arrow while a message or file moves for that contact; in Files, the row of a file being sent or received shows it. It lasts about a minute, then settles. With reduced motion the arrow stays still and the word "now" shows. It shows a word and a direction only, never content, and there is no hover preview. The Home mini map, the Contacts map and the compact strip follow in 0.4.5.
- See who your agents are talking to, right now (U3-map, S1; b11 §32). The Agents page has a new Map view, "Live connections": each agent is a box showing its AI app, its contacts sit on the right (the top 12, then "+N more"), and a line appears for people who exchanged something in the last 24 hours. A short dash travels the line while a message or file is moving. Quiet contacts are behind "Show quiet". With reduced motion, nothing travels and the word "now" shows instead. The list stays the text alternative. The map shows names and words only, never message content, and clicking a box or line opens that conversation in Messages.

## [0.4.3] - 2026-10-28

### Added

### Security

- The submitter applies the pre-audit rules before beta traffic (AUDIT-FABLE-OCCv2-1 FA-1, FA-3; M1-10a): an item from an account with code (a smart account or a delegated address) is sent in its own transaction from the first item, so it cannot make other people's items fail; every transaction's gas limit is its simulated gas plus a small fixed margin; and an item already recorded is reported as already recorded without being sent again, counted against the sender's IP rather than the signer's limit. It logs no request, IP or signature.
- The submitter refuses an item whose signature check would make it pay unusual gas, stops serving a signer whose own transaction failed at inclusion although it passed every check, replaces a transaction that is stuck with raised fees and otherwise queues its items again so a lost slot never blocks later ones, and limits status and health requests per IP (M1-10a, IR-M1-10a-1).
- The test-credits faucet limits each agent to one claim per day, limits claims and requests per IP, and holds a global daily cap, because new agent identities cost nothing (M1-10b). It uses its own key, separate from the submitter's, and logs no request, IP or agent address.
- The local approval page opens your browser and shows notifications only through programs at fixed system paths, never ones found through your PATH, and alerts you at most once every 30 seconds however many approvals are waiting (M1-11a-b, IR-M1-11a-b-1).
- Requests to the encrypted drop are now signed inside your agent's key store with a key used for nothing else (M1-1g-e, S2, 04 §2.1, 07 §5.4): it signs only uploads, commits and deletes in the drop's fixed format, refuses anything else, and never hands out key material.
- Your agent's key store can now sign an encrypted-drop delete with the drop key of the older key epoch a file was uploaded under, so delete-on-receipt can keep working after a key rotation (M1-1g-f, S2, 04 §2.1, 07 §5.4). Only deletes can name an epoch, never a future one, and every check runs before a key is read. The drop adapter passes the epoch (M1-1g-g).
- RPC endpoints, shipped or added by the user, are treated as secrets and never logged or returned: every read-client error is a fixed-code `ChainError` with no address, path or query (M1-4a, IR-M1-4a-1 M-2, I-7). An owner's own endpoint may carry its provider key in the path. Endpoints must be `https://` with a public host name (no IP address, no local or special-use name), with no user info, query or fragment; in Node, private and loopback addresses are refused at resolve time and the checked address is pinned for each request (`nodeRpcFetch`, 04 §4, IR-M1-4a-1 M-1). Requests never follow redirects, and only read methods are sent. The client can neither type nor encode an admin, upgrade or module call, and offers no EIP-3009 deposit until the contracts accept it (AUDIT-FABLE-OCC19-1 M-1, L-1).
- No RPC endpoint address can be read from the chain client object any more, including through `extend`, a namespaced action, an `onError` callback or the transport; and the product path refuses to build a read client over a plain `fetch`: it needs the address-checked fetch that refuses private and loopback addresses at resolve time. This guards against wiring mistakes, not against a malicious caller in the same process (M1-4b, IR-M1-4a-2 R-1 to R-3, IR-M1-4b-1 L-1, I-7, 04 §4). Credit history ignores events from any address other than the configured fee vault and zero-amount deposits, sweeps and withdrawals (IR-M1-3b-1 I-2).
- Proof checks now verify the signing agent's owner-signed profile and require the message's sender to match it (M1-4d-b, S2, 07 §8, IR-M1-4d-1 M-1); a profile that is not signed by its owner, or that had expired, is refused. Disclosed content is not yet credited to the signing agent: full sender attribution is in development. Not user-facing yet.
