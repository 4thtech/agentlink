# Changelog

All notable changes to AgentLink are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). How versions, tags and releases work is described in [`docs/process/versioning.md`](docs/process/versioning.md). Until 1.0.0 (the M3 mainnet beta), a minor version may contain breaking changes; each is marked **BREAKING:**.

## [Unreleased]

### Added

- Monorepo skeleton (M0-2d): pnpm workspace with Turborepo, strict ESM TypeScript with project references, ESLint, Prettier, Vitest and Changesets; a stub package for every directory in the repository layout; manifest checks (MIT licence, no install scripts) inside `pnpm lint`; and CI strict mode (`.github/ci-strict`), so a missing root script now fails CI. All packages are private stubs and nothing is published yet.
- Redacting logger `@agentlink/log` (M0-8): zero-dependency structured logging for Node, browsers and Workers that redacts secrets by field name and by value shape at every level and logs URLs as their origin only, and a secret-canary test helper that fails CI when a known fake secret reaches any log line. Console output is banned outside the logger and the CLI's user-output channel.
- Architecture boundary guards (M0-10): package layering (which package may import which, no cycles), primitive libraries (`@noble/*`, `@hpke/*`, `nostr-tools`, `viem`, `aws4fetch`) and `crypto.subtle` confined to their packages, Node built-ins confined to `@agentlink/node` and `apps/cli`, and a per-package runtime-dependency allowlist where every entry carries a justification. Enforced twice: ESLint zones (including dynamic `import()`, `require()` and relative paths that leave a package) and `tools/deps-check`, which runs in `pnpm lint` and therefore in `ci-gate`. The policy lives in `tools/deps-check/policy.mjs`.
- Cross-runtime test-vector harness (M0-9): `pnpm vectors:check` runs every vector suite in Node, Chromium, Firefox, WebKit and workerd. Each runtime must report its own identity and pass every committed case, and the run may not change anything under `test-vectors/`. CI also checks every committed vector file against its independent generator. Includes the vector file format and schema, a placeholder SHA-256 suite from published NIST and RFC values, and runbook RB-06. There are no protocol vectors yet.
- Protocol test vectors for M1a (M1-1h): 15 suites, 975 cases (471 of them rejection cases). They come from independent Python generators with hash-pinned dependencies (`cryptography`, `coincurve`, `pycryptodome`, `pyhpke`, `rfc8785`). They include the official RFC 5869, RFC 4231, RFC 8785, RFC 9106, RFC 9180, BIP-340, EIP-712 and NIP-44 v2 vectors. AgentLink cases cover key derivation, canonical encodings, the envelope (hash, AEAD, signature, strict structure), the CEK wrap (including every small-order X25519 point), `SignedOwnerAction`, the AgentCard and `cardSig`, the pairing proof, the safety code (signed handshake and ack recomputed), agent ID and fingerprints, and the `ALKS` and `ALKO` file formats, each with rejection cases. Suites whose code has not landed are pending (`test-vectors/pending-suites.json`): CI warns for each one, fails once its module exists, refuses to let the list grow back against `main`, and a release fails while an M1a suite is pending. A suite may declare fewer runtimes only by citing a spec runtime table (`keystore-file`: Node). CI installs the generator dependencies and checks every file byte for byte.
- Crypto base layer `@agentlink/crypto` (M1-1a): strict canonical encodings (bare and `0x` lowercase hex, base64url without padding, decimal uint256, UTF-8), each rejecting every non-canonical form instead of normalising it; SHA-256 and keccak-256 through `@noble/hashes`; BIP-340 tagged hashes with the protocol tags `agentlink/envelope/v1` and `agentlink/owner-action/v1`; RFC 8785 JSON canonicalisation with a strict parser that rejects duplicate keys, lone surrogates and non-finite numbers; a constant-time byte comparison; `randomBytes` from `globalThis.crypto.getRandomValues` only; and a best-effort `wipe()` whose limits are documented. The `jcs` and `tagged-hash` vector suites now run in all five runtimes.
- Key derivation and public identities in `@agentlink/crypto` (M1-1b): HKDF-SHA256 and the exact derivation of the agent keys (EVM, Nostr, encryption and drop keys, with the secp256k1 rejection loop; the EVM key exists only at epoch 0), the agent ID as a lowercase `0x` address (EIP-55 checksum for display only), the encryption key `kid`, a public identity bundle that never contains the drop key, BIP-340 sign and verify helpers that reject keys off the curve and out-of-range signatures, and owner and agent fingerprints with their short, long and domain-claim forms. Every function that takes a master seed or a secret key is exported only from the restricted subpath `@agentlink/crypto/keystore`, which the boundary guards allow only for KeyStore backends (`packages/node`) and the vector harness. The `hkdf-derive` (with the agent ID cases), `bip340` and `fingerprint` vector suites now run in all five runtimes.
- Envelope encryption in `@agentlink/crypto` (M1-1c): the content key is wrapped for each recipient with RFC 9180 HPKE (mode Base, X25519, HKDF-SHA256, AES-256-GCM, through `@hpke/core`) and bound to the envelope ID; small-order X25519 keys are refused in both directions by an explicit all-zero shared-secret check, because not every runtime's WebCrypto makes it. The payload is AES-256-GCM with a fresh random IV and the envelope header as additional data, so changing any header field, including recipient order or `createdAt`, fails decryption. Adds the strict v1 envelope parser, which also enforces the G-2 limits (1 to 8 recipients with distinct `kid`s, and at most 17 152 bytes of `aead.ct`, checked before decoding, so every envelope it accepts fits the 24 576-byte envelope limit), `envelopeHash`, and the envelope signature under the `agentlink/envelope/v1` tag. Unwrapping a recipient's content key takes the envelope ID, never an HPKE `info`, and signing applies the envelope tag itself; both are exported only from `@agentlink/crypto/keystore`; the fixed-randomness test seam (one `@agentlink/crypto/testing` entry shared with M1-1f) is never built or exported, and deps-check and ESLint also refuse a relative import of it from crypto production code. The `hpke` and `aead-envelope` vector suites now run in all five runtimes.
- Policy, approval and proof types `@agentlink/types` (M1-2b): the policy document in its strict JSON form (06 §3, G-32), with the exact defaults, per-contact proof rules, sorted agent-ID lists and USD amounts as strings in one spelling; it now replaces the placeholder inside `policy.set`. An exact USD helper (integer micro-dollars: parse, compare, add, round up to cents, compare a terms price of any size). The G-7 constants (clock skew, owner-action lifetimes, approval TTL, nonce retention, budget window). A strict `approval-request` context for each approval tool, with the commitment scope, the fee and the policy rules that asked, and the 24-hour request TTL checked. ProofPack v1 (07 §8) with the Record and Receipt JSON forms, ProofStatus (06 §2.4) and the common tool-result shape (06 §1). Anything malformed is rejected, never completed with defaults. Some choices are proposed for spec confirmation (listed in the PR).
- EIP-712 and the AgentCard in `@agentlink/crypto` (M1-1e): EIP-712 typed-data hashing (checked against the EIP's own example and, in the unit tests, against viem); canonical secp256k1 ECDSA signatures, `0x` + r‖s‖v with low `s` and v 27 or 28, where a high `s`, v 0 or 1, a wrong length or non-canonical hex is refused before recovery; the AgentCard type under the chain-agnostic domain `{name: "OCC AgentCard", version: "1"}`, a strict parser for the card JSON form (and for its JSON text, refusing duplicate keys and `1.0`, `1e3` or `-0` on the token), `sha256(JCS(card))`, and `cardSig` and `cardAgentSig` verification, with both signatures required for an invite or handshake card; signing is only in `@agentlink/crypto/keystore`. viem is a test-only library in `packages/crypto` (deps-check and ESLint refuse it in runtime source and runtime dependencies). The `eip712` vector suite now runs in all five runtimes.
- Owner passphrase wrap, file KeyStore format, pairing proof and safety code in `@agentlink/crypto` (M1-1f): Argon2id v1.3 (RFC 9106) through `@noble/hashes`, run asynchronously; the 04 §2.8 `password()` rule for a generated 120-bit code (base32, spaces, dashes, lower case and 0/1/8 accepted) and for a chosen passphrase (strict UTF-8, no control characters, NFKC); code generation from 15 random bytes; the `ALKS` v1 file KeyStore and the `ALKO` v1 owner seed wrap (AES-256-GCM over the whole header, separate HKDF labels and magics so neither opens as the other, KDF floor and cap and the agent ID checked before the KDF, the seed checked against the agent ID or the owner keys after it, one error for a wrong secret and a damaged file); the owner wrap refuses relay publication and, on a file-KeyStore machine, a chosen passphrase. The pairing proof (HMAC-SHA256 under `proofKey`, never the raw invite secret) and the safety code (`codeCommit`, a constant-time reveal check, the role-ordered transcript, `pairingDigest` and the 12-digit code). Secret-handling functions are only in `@agentlink/crypto/keystore`. The safety code is computed only after the revealed nonce opens the commitment. A chosen agent passphrase needs at least 12 characters, the owner secret is accepted only from a prompt, and two probes answer whether a candidate unlocks the owner wrap or an agent file (for the agent and owner secrets must differ rule) without handing out a seed. Deep imports into a workspace package's `dist/` or `src/` are now refused by the boundary guards. The `owner-wrap`, `pairing` and `safety-code` vector suites now run in all five runtimes and `keystore-file` in Node; the signed handshake and ack recomputation cases moved, unchanged, to a new `safety-code-recompute` suite, pending under M1-1c.
- Cross-runtime schema tests (M1-2c): the `@agentlink/types` tests run in Node, Chromium, Firefox, WebKit and workerd (`pnpm test` in the package; `pnpm test:node` for Node alone). Each run reports its runtime, so a silent fallback to Node fails, and the workerd run covers zod's interpreted (no `new Function`) parsing. The `checks` CI job installs the Playwright browsers for it.
- KeyStore interfaces and NIP-44 in `@agentlink/crypto` (M1-1g): the key interfaces of gap G-2. `EnvelopeKeys` (sign an envelope, sign a seal or relay login, NIP-44 encrypt and decrypt, open a content key) is shared by the agent's `KeyStore` and the owner's session, so both use one path. No method hands out a private key or a seed, signs an untagged digest or opens HPKE for another purpose, and only decryption and the public-key lookup take an older key epoch. Owner signatures come only from a short-lived session unlocked with the owner's presence, which ends on expiry or lock and wipes its keys; it signs envelopes, seals and relay logins for the owner channel, and nothing else on Nostr. EIP-712 signing by the agent and owner keys. NIP-44 v2 encryption with strict checks (size, version, base64, MAC before decryption, exact padding), Nostr event ids and signature checks, and a NIP-59 gift wrap whose one-time key never leaves the package. Opening a content key goes through M1-1c's unwrap, with the agent's key of the requested epoch or, in an owner session, the owner's key. In-memory KeyStores for tests only, in the package's one test seam, which is never built or published. The `nip44` vector suite (148 official cases) now runs in all five runtimes.
- Core skeleton `@agentlink/core` (M1-7a): `AgentLinkClient.create` over a KeyStore, a Store, a store cipher and an approval channel. The `Store` interface covers every table of the local store schema (07 §3, including the G-9 tables) with synchronous, all-or-nothing transactions, compare-and-set counts, and keys, unique constraints, enums and value types enforced by the store itself; an in-memory Store serves tests. The `ApprovalChannel` interface only carries requests to the owner and brings back what the owner signed; it approves nothing by itself. Identity issues the agent card signed by the owner and endorsed by the agent key (both checked before anything is stored), records the agent ID derived from the seed with a random storage prefix, and rotates to the next key epoch with a new card while older keys keep opening history. Until the owner completes a rotation the agent refuses to send. Contacts are keyed by agent ID. A received card is first staged, and becomes a contact only when its handshake completes, in one store transaction, so a replayed card changes nothing. A re-pair needs unchanged owner keys and an epoch that is not lower, and is never allowed for a revoked agent or for the agent itself. Card updates need a higher epoch from the same owner, and no card may claim another agent's key. A blocked or removed contact's later envelopes are dropped; a removed contact stays as a tombstone. Cards, names and relays are stored in columns marked for encryption at rest, sealed through a store-cipher interface; the real cipher (AES-256-GCM under the store key) lands with M1-8b, so nothing is encrypted at rest yet. Display names are marked self-declared, and a name the owner chose is kept. The G-9 limits are named constants.
- Specification (IR-M1-7a-1, proposed; owner confirms at merge): 07 §3 stores agent cards encrypted (a clear card would let a stolen store file confirm guessed contact names through `nameHash`), adds the contact status `removed` (a tombstone whose later envelopes are dropped, 02 F-14) and a `pairings` table for pairings in progress, lists the extra contact and identity columns and the key rule, and names the rules the core enforces rather than the store. Backlog: new card M1-1g-d (owner-only key epoch advance), hand-offs to M1-7b and M1-7c, and M2-2d owns the owner-surface store schema.
- Gift wrap and unwrap in `@agentlink/transport-nostr` (M1-5a): an envelope is sent as the content of an unsigned kind 14 rumor tagged `["agentlink","1"]`, exactly its JCS text, sealed (kind 13) through the sender's `EnvelopeKeys` and gift-wrapped (kind 1059) once per distinct recipient key with an ephemeral key created inside `@agentlink/crypto`, NIP-44 v2 throughout, and seal and gift-wrap timestamps back-dated at random by up to 2 days. Envelopes over 24 576 bytes are refused before wrapping, and the final size of each gift wrap and its relay frame is reported for the relay checks. Unwrap fails closed: the gift-wrap and seal signatures must verify, the rumor key must equal the seal key, the `agentlink` tag must be present, the rumor content is size-checked before it is parsed, the envelope must pass the strict parser, and the seal key must equal the envelope's `from`. Interop is tested in both directions against the `nostr-tools` NIP-59 reference (new devDependency, tests only).
- Backlog and README update after the 14 Oct 2026 merges: card statuses and pull request links, new follow-up cards (M0-2h, M0-26, M1-3h, M1-3i), and the README Status and Roadmap now list the merged M1a crypto foundations, the G-2 specification, the design drop D1 and the notary contract work.
- Build plan "At a glance" (building blocks, stages, external services) and plain-language explainers on messaging, files and payments under `docs/explainers/`.
- Public documentation source under `docs-site/`: a user guide and technical docs (one GitBook space each, for publishing through Git Sync), organised by Diátaxis. Concept, security and pricing pages describe the published design; every other page is an outline marked planned with the version that fills it in. Upkeep rules in `docs-site/MAINTAINING.md`, a docs pass per milestone (backlog cards DOCS-M1a to DOCS-M3), and a Definition of done rule that a milestone or release is done only when the public docs are updated.
- Process (DOCS-RB): runbooks for every repeatable procedure (`docs/runbooks/`), lessons learned (`docs/lessons/`), a role-based "Start here" map with a time-boxed onboarding track (`docs/README.md`), and a `GEMINI.md` pointer so Gemini CLI loads `AGENTS.md`.
- Design drops D1 and the first pass of D2 (DESIGN-D1): brand assets (logo, app, tray and UI icons, colours, social images), design tokens in four themes with Geist fonts, in-chat and terminal copy, 31 component specs with a reference bundle, 46 screens (local approvals app, owner console, desktop apps, cloud agent, verify, invite, pay, pricing) and the live sources, under `docs/design/` with a `MANIFEST.md` per folder. Status recorded in `docs/design/README.md`: D1 delivered with partial points, D2 partial (no prototypes or rationale notes yet).
- Test timeouts for the repository tools tests (M0-10d): the console-ban test now does the cold ESLint start once in `beforeAll` under a 60 s hook timeout, and `tools/vitest.config.mjs` sets a tools-wide `testTimeout` of 20 s, so a cold or loaded CI runner no longer fails the first test. No assertion changed.

URL stripping now also drops paths written with backslashes (`https://host\v2\key`), JSON-escaped slashes and `https:\\host`, protocol-relative URLs (`//host/path` becomes `//host`, user info dropped, IPv6 kept), and keeps the backslash that escapes a quote after a URL. New gap G-46 (requirement: one plaintext for every recipient).
