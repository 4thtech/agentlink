# D-54: Headless KeyStore (G-31)

- **Status:** Decided (14 Oct 2026)
- **Date:** 2026-10-14
- **Specs:** 04, 07
- **Index:** [all decisions](README.md)

## Decision

**Headless KeyStore (G-31).** AgentLink works where coding agents run without an OS keychain (Linux containers and devcontainers, WSL, SSH sessions, servers without Secret Service). The OS keychain stays the default and is always tried first; there is no forced file mode. Only when no keychain is usable **and** the user opts in, in an interactive terminal (`init --keystore file` or the `init` question), are the agent's keychain items kept in a **passphrase-locked file** (`~/.agentlink/keystore/<agentId>.alks`, format `ALKS` v1): Argon2id (m = 64 MiB, t = 3, p = 1, the same as the owner passphrase wrap; unlock asynchronous, up to about 5 s accepted) and HKDF into AES-256-GCM over an authenticated, versioned header bound to the expected agent ID, through `@agentlink/crypto` (`@noble/*`); file mode 0600, directory 0700, descriptor-based owner, symlink and `realpath` checks, a locked re-read before every write, zeroisation. A generated 120-bit unlock code is the default. The MCP server unlocks it from a passphrase file mounted at run time (recommended) or an environment variable (allowed, documented as weaker). The choice is never silent and never switches by itself. **The owner key** is never unlocked from an environment variable, file or any non-interactive source; agent and owner secrets must differ (checked both ways). On these machines the owner key is created in a separate step (`owner init` †), lives in `owner.alko` and requires a generated 120-bit owner code, because copies of the machine carry the file. "Interactive only" is a UX guard: an agent that fakes a terminal and runs the owner step itself voids owner presence on that machine; what protects the owner is doing that step personally, the passkey (M1b) and approving from the owner's own device. Owner operations use the passphrase prompt in a terminal the agent does not control (M1a), port-forwarded local approval (M1b) or the console. Threat delta: none for the agent key against a same-user agent (04 §2.2); weaker than a keychain against copies of the disk or image unless the passphrase source stays off it. Proposed defaults, owner confirms at merge: M1-8f in M1a off the critical path; no forced file mode; the environment-variable source allowed with the documented conditions; parameters kept up to about 5 s unlock; in M2, headless machines keep the owner key off the box by default and approve from the console. Open: Node's built-in `crypto.argon2` if unlock exceeds 5 s (an allowlist decision). Spec: 04 §2.8, 07 §9. **Resolves G-31**
