# D-144: User-facing "agent" becomes "ID" (W7-ID-RENAME)

- **Status:** Decided (owner, source: owner Decision 56, 2 Nov 2026; Q1 to Q5 answered the same day with the recommended answers)
- **Date:** 2026-11-02
- **Specs:** 08, 11
- **Index:** [all decisions](README.md)

## Decision

**User-facing "agent" becomes "ID" (W7-ID-RENAME).** In every user-facing text, the identity AgentLink creates for an AI app (its keys, inbox, contacts and rules) is called an **ID**; an AI app runs many AI agents and chats, and all of them use that app's one ID through the MCP. "AI agents" (the AIs) stays, as do the product name AgentLink, the protocol, data and DB names, code identifiers, routes, the `owner add-agent` command and the `--agent` flag (`--id` and a `/ids` route are added as aliases). The long identifier formerly "Agent ID" is the **ID number**; the agent card or profile is the **ID card**. An ID's name is the name people see (contacts and invites show it); the AI app is shown next to it only on this computer ("Tali · Claude Code"). A new ID's default name is the owner's name if known, else the AI app's name, never "{App} agent". "Ana (Claude Code)" for contacts is deferred: the protocol carries no AI-app field (M2). Also built: a first-run explainer card, "Used by …" on each ID, approvals that name the ID, and a vocabulary guard. Amends the user-facing words of D-138, D-140 and D-143; the protocol, I-1 to I-10 and the data model are unchanged. Specs: 11 §5.1, §5.2, §5.3, §5.6 to §5.8; 08 §1; 02 light. Tasks: W7-ID-B0 to W7-ID-B7 (06 follows with B4). Not a renumbering of the brand decision D-56 in this log.
