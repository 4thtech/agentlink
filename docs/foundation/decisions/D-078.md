## Decision

**One owner, many local agents; `init` for one harness (M1-9t).** Decided by Tali in chat, 2026-10-16. (1) Under one OS user, **one owner key** (the `owner` item, 04 §2.2) owns any number of local agents, typically one per harness. `agentlink owner init` stays once per OS user; when an owner key exists it creates no second owner and points to **`agentlink owner add-agent --agent <name>`** †, which signs exactly one first card for exactly that agent with the existing owner key, in one owner operation with owner presence (04 §2.8). (2) `init --harness <id>` targets one harness; **`--harness none`** creates the agent identity only (no separate flag); declining every proposed harness change never removes an identity (06 §7). (3) Agents under one OS user are kept apart by **logical isolation, not a security boundary**: each has its own seed, store, Nostr identity, policies and approvals, and an owner action binds to one agent (04 §2.5.1), but every agent runs as the same OS user and can read the others' keys and stores (G-1 residual, D-67). **Derived (author; proposed, owner confirms at merge):** the add-agent copy and refusal rules, the OpenCode and Antigravity config rows, and `--config <path>` (only with `--harness opencode` or `antigravity`, under the 04 §4 realpath rules).
