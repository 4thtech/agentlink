## Decision

**One Touch ID creates an agent and connects its AI app (W5).** **Decided by Tali in chat, 2026-10-29** (Decision 43, W5: one gesture for "create agent + connect AI app", with a 04 §2.8 amendment and a Fable review). *Details proposed, owner confirms at merge (W4-ONE-TOUCH):* (1) When the owner picks an AI app on the screen that creates an agent (first run, or New agent in the app), the one gesture signs the agent's first card, first `policy.set`, first `agent.label` and its first `app.connect` for that one app; on first run the same gesture also creates the owner. It is one owner operation under 04 §2.5 "One entry", like card + policy + label today: no new op, no batch object, no unlock session. (2) Because `app.connect` binds the agent's `agentId`, the agent's seed is created at the **begin** step and held in memory only, at most 120 s, bound to the page session and usable once (the first-run owner-seed hold, 04 §2.3.1); begin reserves the folder name, computes the `changeId` for the new `agentId` and fixes the ordered plan of unsigned bodies. (3) One challenge binds the plan: `SHA-256("agentlink-create-connect-v1" ‖ nonce ‖ SHA-256(JCS(statement)) ‖ SHA-256(JCS(plan)))`, single use, 120 s; finish takes only the nonce and the presence proof, and the restricted owner session signs exactly the plan's bodies in order, so the plan cannot be replayed, split or extended. (4) Order: owner (first run), agent keys and folder, card, policy, label, then `app.connect`; the owner key is wiped before the config file is written last. (5) A failure up to the label is all or nothing as today (a crash before the verified card leaves an orphan that `doctor` names and offers to clean, as today); a failed `app.connect` store or entry write keeps the complete agent (decided by Tali in chat, 2026-10-29, Decision 45), leaves the config file unchanged, records the `app.connect` as not applied and answers `created_not_connected` ("{label} is ready. {app} isn't connected yet." with Connect; on first run still with the owner code). (6) A new begin replaces a held plan within the same page session only; other sessions are refused (decided by Tali in chat, 2026-10-29, Decision 45). A wrong owner code does not consume the plan (usual tries and backoff; decided by Tali in chat, 2026-10-29, Decision 45); the folder reservation is released whenever the plan ends unused. (7) With the owner code, the plan is bound server-side only, as on every owner-code prompt (decided by Tali in chat, 2026-10-29, Decision 45). Threat model unchanged (04 §2.5, same-user shell): the new agent's seed in memory for 120 s is the first-run owner-seed residual. Spec: 04 §2.3.1, §2.5, §2.5.1, §2.8; 06 §7; 08 §1; 11 §5.8.
