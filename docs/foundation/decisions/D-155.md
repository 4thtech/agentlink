# D-155: The menu bar widget: a living brand-mark icon and a read-only popover

- **Status:** Decided (owner, 16 Nov 2026: brand-mark icon and animations, hollow ring and filled dot, opening clears the ring, the sections, previews on with a switch, read-only, the menu bar switch with Windows quit-on-close); mechanics proposed, owner confirms at merge
- **Date:** 2026-11-16
- **Specs:** 04, 08, 11
- **Index:** [all decisions](README.md)

## Decision

**The menu bar widget: a living brand-mark icon and a read-only popover (TRAY-SPEC, release 0.5.9; amends b11 §17.4 and §25.4 "no message text" for the widget only).** **Decided by Tali in chat, 2026-11-16.** Purpose: people see at a glance, without opening the app, what their AI exchanged and whether anything needs them. (1) **The icon is the brand mark** (two brackets and a diamond) in the macOS menu bar and the Windows notification area, replacing today's ring. Its shape shows the state, never its colour: static variants `connected`, `approvals`, `paused`, `offline`, `update`; event-driven frame animations **message in** (the diamond slides in), **AI sent** (it slides out and back), **approval** (it grows once, then the `approvals` variant) and **connecting** (it breathes, looping only while connecting); paused, offline and update change with a short fade. **Reduced motion** (the OS setting, read at each trigger, or the app's own motion `off`) shows the end frame only, never frames. (2) **Two marks, two shapes.** Unread is a **hollow ring**; approvals waiting is a **filled dot**. **Opening the widget clears the icon's ring**; the per-contact counts in the widget stay until that chat is opened in the app. Approvals keep the dot until they are decided. (3) **Left click opens a popover widget** that replaces today's plain tray menu (360 px wide, height from the content, at most 560 px; it hides on a click outside and on Esc); **right click** shows a minimal native menu: **Open AgentLink** and **Quit**. Linux keeps a native menu. (4) **Sections, in this order:** status (the ID's live word, b11 §25.2); **Needs you** (approvals waiting and new files); **Connected now** (per ID, its AI apps working, ready or idle from the live MCP sessions, 08 §1 "Live AI-app status"); **Contacts** (the last exchange only, "Active now" or "Today"; the protocol has no presence, so never "online"); **New messages** by contact (count, time and a short preview); **Today** (an hourly timeline of messages in and out, proofs and files since local midnight); **Live** (the newest activity entries); a footer (Open AgentLink, Pause or Resume, Update ready, Quit). (5) **Previews on by default, with a switch.** A preview is the newest received message's text as **plain text, at most 80 characters, one line, never rendered as markup**, built by the server (control, format, bidi and separator characters removed, whitespace collapsed, cut on a grapheme boundary with "…"), shown as a text node only, never linkified, never a file name. A Settings switch **"Show message previews"** (on by default) turns them off, and then **the server omits them** (enforced in `GET /api/ui/widget`, not in the page). The owner accepts that a glanceable surface can be read over a shoulder; the switch is the answer. Previews never reach the icon, its tooltip, the pipe, OS notifications, the page title or logs (I-5, I-7). (6) **Read-only.** The widget approves, denies and signs nothing and never shows a presence prompt (it hides on blur, which a Touch ID sheet would cause): **Review approvals, Pause, Resume and Update open the main window** (the widget cannot send a change, so Pause is not done in place). Its window uses the main window's in-memory session and lockdown, and its one preload can only open a page of a fixed list, close itself or quit, each on a user click. (7) **"Show AgentLink in the menu bar"** (Mac) / **"Show AgentLink near the clock"** (Windows), in Settings, desktop app only, **on by default**. Off removes the icon; macOS keeps the Dock icon; on Windows, **while the icon is hidden, closing the window quits AgentLink** (otherwise it would keep running with no way back). (8) **How the shell learns what to show.** The core tells it over the private pipe (08 §8): `tray-state`, `tray-pulse` and `shell-prefs`, numbers, fixed words and booleans only, never text, names, refs or IDs. The shell still holds no cookie, token or content and never calls `/api/ui/*`. (9) **New reads** (08 §1): `GET /api/ui/widget` (unread by contact with optional previews, today's buckets, recent contacts) and an `activity` hint event on `GET /api/ui/events` (`{at}` only). The UI settings gain the booleans `menuBarIcon` and `widgetPreviews` (absent = on). No MCP tool reaches any of it (I-4); nothing new goes to a 4thTech service.
