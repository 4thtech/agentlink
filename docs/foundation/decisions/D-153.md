## Decision

**Forgot your master code? Start over on this computer (OWNER-START-OVER; Mac app, Windows app, browser app).** **Approved by Tali in chat, 2026-11-14** (the feature and a new D-entry, release 0.5.5; the no-sensor path decided the same day: "Let's go with Recommended: type "start over" twice to confirm."). (1) **Entry and order.** A quiet link "Forgot your master code?" under the master code field of the approval card and of every presence prompt, and "Start over on this computer" in Settings › Touch ID & master code › I lost my master code, open `/restore/start-over` (the restore wizard's focused column). It first says what is lost (the IDs on this computer stop working, people need a new invite, their messages can no longer be opened in AgentLink, AI apps lose their ID) and what is kept, and offers **Restore from recovery kit** first (D-147); "Start over instead" is the second action. (2) **Gates, all checked by the server.** The page session of the app host; the typed phrase `start over`; then one fresh confirmation. Desktop app with Touch ID or Windows Hello set up: a real OS sheet the server raises itself through the platform-neutral native helper (macOS `create` then one `ecdh reset` sheet, "start over AgentLink on this computer", a new fixed reason id in both helpers; Windows `create`, the one Hello prompt, then `delete`); typing instead is refused. Browser with a user-verifying platform authenticator: a WebAuthn creation with UV checked as first run checks one (attestation `none`). **No user-verifying presence** (a Mac without Touch ID, a PC without Hello, a browser without a platform authenticator): the person types `start over` a second time on its own confirmation step (an empty field never filled from the first; finish `{nonce, phrase}`, presence `typed`; fresh single-use nonce, same page session, 120 s). Only gestures made and not recognised count toward the wait (60 s doubling, at most 15 min). (3) **Effect, in order.** The IDs' agent IDs and a digest of the `owner` item's ciphertext (`ownerTag`) go to `start-over.json` (0600, no secret); the open ID is closed; `~/.agentlink` is **moved** to `~/.agentlink.backup-YYYYMMDD-HHMMSS` (never deleted; a link is refused, 04 §4); each ID's keychain items are erased by exact name; the owner's six fixed accounts, `owner` last, only if every ID erase succeeded and `~/.agentlink` has not come back; the records are marked done (a failed write is a failure); the app host offers first run with a new master code (FIRSTRUN-ANY-PLATFORM owns those pages). (4) **Partial failure and retry.** Every outcome is answered (`partial` with `move` or `keychain`; never silent). A retry moves what is there now and finishes every unfinished record. When an unfinished record exists and the `owner` item is not the one it recorded, a new owner exists: only the earlier IDs are finished (`earlierOnly`) and that owner's folder and items are never touched. (5) **Not from an AI app (I-4), and what the gates do not do.** Its own route kind (`start-over`: `GET state`, `POST begin`, `POST finish`, fixed paths, no handler) behind the session cookie, CSRF, Host, Origin and fetch metadata; only the app host offers it; no MCP tool, handoff token or agent credential is a session; the engine is not exported from `@4thtech-io/node`. The gates stop web origins, AI apps over MCP and accidents. They are **no protection against a same-user process** (04 §2.5, G-1): it can get a page session, forge the browser creation, claim no sensor and type the phrase twice, and it could move the folder and delete our items without AgentLink anyway; only the desktop app's OS sheet is a gesture it cannot answer. Start over adds no power: it exports nothing, signs nothing as the old owner, reveals nothing and keeps the old folder. (6) **After.** The done screen says to quit and reopen the AI apps (a running `agentlink mcp` keeps the old keys in memory and writes into the backup until restarted) and that passkeys named AgentLink can be deleted in the browser or system settings. Residuals: older `s3:<id>` items beyond the active storage mark, the old Windows Hello key and those passkeys stay. *Open question Q-153-2:* keep the IDs' own keychain items so that moving the backup back restores the IDs (owner still locked), instead of erasing them as approved. Spec: 04 §2.5.4; 08 §1; 11 §5. Card: OWNER-START-OVER. Numbering: D-152 is the files decision of FILES-SPEC-055. Invariants I-1 to I-10 unchanged.
