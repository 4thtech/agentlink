## Decision

**Restore from a recovery kit inside the app; one kit for all IDs; a server-side kit record; Check that my kit opens (design-1112, amends D-117 (A)).** **Decided by Tali in chat, 2026-11-12:** "I'm approving the design and you can start building". The approved design (design-1112, spec §6) includes restore inside the app, so it **amends D-117 (A)**, which kept restore in the terminal only; the terminal command stays. (1) **Restore in the app**, browser and desktop, as a four-step wizard (kit file, recovery code, what comes back, protect and reconnect), from Welcome ("I have a recovery kit"), Get started step 1, Settings › Backup & restore › Restore… and the desktop app's first run; the terminal gets `agentlink restore` (alias of `agentlink backup restore [file]`, with `--check`). Same engine, `KeyImportControl` (04 §2.3.3), same words. No MCP tool restores or checks a kit (I-4). (2) **One kit, all IDs:** Back up in the app saves every local ID of this owner (at most 16) in one gesture, one file and one recovery code; it replaces WP-11's "the open ID". (3) **Per-ID rename on restore** for a name clash, for any number of IDs (a rename map); amends the one-agent rule of `--agent <newname>`. (4) **Presence instead of the typed owner code** on a computer that has an owner: Touch ID or the master code, through a restore-only owner session that opens the owner key to the kit's owner, counts the same as the existing owner code of the 04 §2.3.3 table. (5) **On a computer without an owner, the restore ends with a fresh user-verified gesture** (WebAuthn create with user verification; native presence in the desktop app) that creates the local passkey wrap together with the new master code, as first run does; without a sensor the app refuses and points to the terminal. (6) **Kit record:** the app records each kit save on this computer (time, kit ID, covered IDs, people count), so the status card is true in every browser; it replaces the browser's "kit pending" flag. (7) **Check that my kit opens:** opens a kit with its code and lists what it holds; writes nothing. Authority is unchanged (D-115 E): restore signs no owner action; possession of the kit and its code, typed by a person, is the authority. Threat table T-1 to T-12 in 04 §2.3.3 "Restore in the app". *Route shapes, limits, lifetimes and the record format proposed, owner confirms at merge (WP-R0); Fable security design review before WP-R1.* Spec: 04 §2.3.3, §2.5; 06 §8; 08 §1, §8; cards WP-R1 to WP-R4, WP-D1. Invariants I-1 to I-10 unchanged.
