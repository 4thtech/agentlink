## Decision

**Show in Finder without Touch ID, message history kept as today, and the local-session residual for message text accepted for 0.3.x.** **Decided by Tali in chat, 2026-10-27** (decision 11; MSG-FILES-IO plan owner questions 1 (a), 2 (a) and 3 (a)). (1) **Show in Finder** for a saved received file needs no owner presence: the request carries only the item ID, and the server opens only the file the store recorded for that item, inside the Inbox folder (04 §4 realpath rules), through the OS opener with no shell. It is a new route kind for one fixed local action that signs nothing and writes nothing to the store; every other mutating route still needs presence (D-118). (2) **Message history** is kept as today, for as long as the contact is not removed; no new limit *(amended by D-148, 12 Nov 2026: the owner can delete history on this computer and set retention.)* (3) The documented local-session residual (04 §2.5, D-67) now also covers message text shown on the Messages page; accepted for 0.3.x and revisited before M3. **Threat note (author):** the AI gains no new authority or data (it already reads the same messages through its own tools; I-4); Show in Finder takes no name or path from the request (04 §4).
