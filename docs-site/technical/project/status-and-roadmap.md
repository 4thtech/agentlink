## Where we are

<!-- status-summary:start -->
**Phase:** M0 Foundations nearly complete; M1a (walking skeleton) released as v0.1.0 on 16 Oct 2026 and updated in v0.1.1 on 18 Oct 2026 (pre-alpha); M1b (files, proof, credits) in progress, with the building blocks merged but not yet usable from the CLI or the MCP tools. The repository [README](https://github.com/4thtech/agentlink#status) carries the same status; both are generated from one source file, [`docs/status.yaml`](https://github.com/4thtech/agentlink/blob/main/docs/status.yaml).

**Not yet:** file transfer, proof, credits, the designed local approval page (a functional page with the owner code and a localhost passkey is merged, and `agentlink mcp` opens it when an approval is needed), the encrypted drop service (built, not deployed), the owner console, desktop apps and the cloud agent. They are described throughout and marked "planned" or "in development" where they are not available. v0.1.1 (the `@4thtech-io/agentlink` CLI and MCP server, pre-alpha, testnets only) was released on 18 Oct 2026 and is the npm `latest`; install it with `npx -y @4thtech-io/agentlink init`.

**Testnet:** OCC v2 notary and fee vault deployed and smoke-tested on 14 Oct 2026. Pre-audit; AgentLink does not use them yet. **Mainnet:** After the external audit (M3). Not deployed. **Services:** None deployed yet. The encrypted drop Worker is built and tested locally (M1-27a) and has its deploy pipeline (M1-27b), which goes live once the owner's Cloudflare setup is done; the submitter and faucet are not built yet.

**In progress:** M1b is in progress. v0.1.1 (18 Oct 2026) is on npm `latest`. It carries the fixes and small features listed under the MCP server and CLI. In development, merged but not yet usable from the CLI or the MCP tools: STREAM file encryption, the owner-signed Revocation typed data, multipart upload with streaming encryption for your own storage, the localhost approval page (`agentlink mcp` opens it when an approval is needed), the safe fetch and path guard, the files and proof policy rules, the proof hashing, and file send and fetch in the core (inline or through the encrypted drop, verified before a file is saved). The encrypted drop Worker is built and has its deploy pipeline, but it is not deployed yet: the owner's Cloudflare steps are pending. Still open from M1a: the two-person dogfood between Tali and Denis (M1-23). Next in M1b: sending files through the tools, the designed approval page and proof.

**Next:** Wire file sending into the tools (encryption, storage and the encrypted drop once it is deployed), add `agentlink ui`, run the two-person dogfood, then finish M1b: proof and credits on testnets, and cut the 0.2.0 release.

## Gates

- **M1a:** the two lead developers' agents pair and sync project status through AgentLink, and complete a negotiation over Talk without on-chain proof.
- **M1:** 10 internal testers on at least 3 harness combinations complete install, first message, notarized handover, approvals, verification and a proof of agreement on testnets; no crypto vocabulary in default flows; install to first message under 5 minutes.
- **M2:** 20 to 50 external testers on testnets; the same UX bar, including the desktop apps and the browser counterparty.
- **M3:** first paid notarizations; zero security incidents; an external audit of the contracts with all high and medium findings fixed.

## Not in the beta

A human chat app, real-time chat, readable file hosting or archiving, custody of funds or keys, a project token, payments between parties (later), and forward secrecy for archived messages.
